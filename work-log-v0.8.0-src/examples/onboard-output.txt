  「让第二个 agent 自动接入」其实是两件事，自动化程度恰好相反：
    · **机械接入**（工具侧）**本来就自动** —— `post` 对未知名字当场注册，没有 `join` 子命令，
      那一次心跳顺带就把协作界面拉起来了；
    · **认知接入**（它那侧）**不可能自动** —— 模型没有推送通道，除非义务句落进
      它启动时**一定会读到**的文件里。

  这条命令管的是后半段：把「该报什么名、往哪报、多久报一次」写成一段可直接粘贴的协议。
  默认**只打印** —— 连看板目录都不会顺手建出来；给 `--to` 才落盘，而且落盘是**幂等**的。

## 协作看板（work-log）：你要报到

本机有一块 agent 协作看板，别的 agent 正靠它互相通报进度：

    看板目录：<家目录>/demo-project/.workbuddy/work-log
    启动方式：<家目录>/demo-project/.workbuddy/work-log/worklog      （这块板自带的引导脚本，它自己找引擎）

**义务：每个动作后都写一条心跳；收工必须写 `--done`。** 这是硬性的 ——
不写就等于你从未接入过（名单里有没有你的名字都不算数），看门狗会把你标成
「从未接入」或「疑似卡死」，你的沉默会以告警的形式出现在别人眼前。
`--dir` 一律显式传上面那个绝对路径：引擎**没有默认落点**（缺 --dir 会退 2 并指路），别靠猜。

```bash
D="<家目录>/demo-project/.workbuddy/work-log"
WL="$D/worklog"        # 板自带；已把 --dir 钉死在 $D，所以换台电脑也能直接跑
"$WL" post --dir "$D" --agent opencode2 --tag 执行 --text "做了什么 / 结论是什么"
"$WL" brief --dir "$D" --agent opencode2    # 取别人的新动态 + 谁在等我回答
"$WL" post --dir "$D" --agent opencode2 --tag 任务完成 --done --text "收工"
```

- **名字要钉死**：`--agent opencode2` 里的名字就是「你」。如果这块板上可能有两个会话，
  别把名字留在共享文件里 —— 给每个会话各自设
  `export WORK_LOG_AGENT=<名字>`，或按目录登记一次：
  `"$WL" identity set --agent <名字>`（之后在这个目录不传 `--agent` 也能认出你）。
  两个会话用同一个名字 = 共用一份心跳和游标，板上看不出来。
- **长命令前先占位**：超过约 60s 的命令要先跑
  `... hold --agent opencode2 --seconds 600 --text "跑 X（约 N 分钟）"`，
  否则看门狗只看静默时长，会把正在干活的人判成疑似卡死（实测被连报两次）。
- **收到告警先分清两种**：「疑似卡死」⇒ 它多半在跑长命令（见上一条）或真卡了，看日志 / 接管；
  「判定为**离线**，不是卡死」⇒ 别去救（进程多半早没了）。**确定它不会再回来**（进程关了、
  任务砍了）⇒ `"$WL" retire --agent <它> --note "为什么判定不回来了"` 宣告离场，告警就此停；
  宣告错了它一条 post 就自动复位。
- `ask` / `reply` / `await`：`await` 退 **0**=有答复 · **1**=超时（可以自己拍板）·
  **3**=对方已收工（别等了）· **5**=**互相等待**（你在等的人正在等你 ⇒ **先回答它**）。
  这四个码的处置各不相同（1 是再等等、3 是自己拍板、**5 与 1 相反**），别混为一谈。
- **只刷心跳不算在线 —— 你还得能被叫醒。** 上面那条讲的是**你问别人**；要让别人问你时
  你真收得到，必须挂一个**唤醒器**（响应式会话没有后台轮询，没人叫就不会醒）：
  `"$WL" waker --dir "$D" --agent opencode2 --window-min 45`（放后台跑）。
  板上一有冲你来的事（用户新喊话 / 有人 `ask` 到你）它就**退出** —— 退出即唤醒你这个会话；
  **它不替你回话**。窗口到点会自己退出，你被唤醒后重新挂上，这就是「保持在线」的续期循环
  （靠的是这个循环，不是某个进程永不退出）。
  **醒来第一件事**：`"$WL" brief --dir "$D" --agent opencode2 --peek` 查有没有「待你回应」，
  收尾再 `read-user` 取用户喊话 —— 漏了这一步，别人 `ask` 到你就是**断的，而且不报错**。
- 退出码：**2**=参数错 · **3**=抢锁失败/对方已收工 · **4**=熔断（写太快）· **70**=工具坏了。
- 动共享资源（文件、端口、数据库）前先 `lock`，做完 `unlock`。
- **拿不到对方的回答就如实上报、并允许自己拍板；编造对方的话是明确禁止的。**

   落点（「那个 agent 启动时一定会读到哪个文件」）：
     user             <家目录>/.workbuddy/MEMORY.md
                      WorkBuddy 用户级记忆：跨工作区、每会话注入
     opencode-global  <家目录>/.config/opencode/AGENTS.md
                      opencode 全局指令：**任何目录**开会话都读
     claude-global    <家目录>/.claude/CLAUDE.md
                      Claude Code 全局记忆：跨目录
     repo             <会话工作目录>/AGENTS.md
                      仓库级：opencode / Codex / Cursor 等在**该目录**启动时读
     claude           <会话工作目录>/CLAUDE.md
                      Claude Code 项目级
     gemini           <会话工作目录>/GEMINI.md
                      Gemini CLI 项目级
     cursor           <会话工作目录>/.cursor/rules/work-log.mdc
                      Cursor 项目规则
   也可以直接给一个文件路径。
  ⚠ 三个必踩的坑：① 往仓库跑 /init 会覆盖 AGENTS.md；
     ② **已开着的会话不会捡起新写的文件**，对方要新开会话才生效；
     ③ 写在某个仓库里的协议只对**在该目录启动**的 agent 生效 ——
        换个目录开会话就断，所以跨工具链优先用 user / opencode-global。

    ↑ 退出码 = 0。片段天生带「坐标 + 报到义务」，所以它**必然能通过 `doctor ③`** ——
      这是刻意的：`onboard`（开药）与 `doctor`（验药）共用同一道门槛 `_path_forms()`，
      不会出现「自己开的药、自己验不过」这种最难查的错。回归组 `[35]` 把这条钉住了，
      还配了反向对照：**把坐标留下、拿掉义务句，那个 ✓ 必须立刻掉下来**，
      以证明那个绿不是碰巧为真。

      片段里「拿不到对方的回答就如实上报、并允许自己拍板；编造对方的话是明确禁止的」
      不是客套 —— 它是真机 3 轮验收里被真模型踩过，才写进协议里的。

  ★ 上面这段片段里，**一个本机绝对路径都没有** —— 这不是省略，是 2026-09-25 起的一条硬约束。
    它的作用不是"好看"：片段是要**离开这台机器**的（抄进对方的记忆、拷到别的电脑）。
    写死 `/Users/<某人>/…/work_log.py` 的那一刻，这段协议在第二台机器上就是一条死链，
    而且失效是**静默**的 —— 对方照抄、报个"文件不存在"，然后不再报到。
    也就是本工具历史上最讽刺的那次失效（协议写对了、人却对不上）的复现路径。

    现在它只写两样东西：**看板目录**（本来就是数据、跟着板走）+ 板里的
    `<看板>/worklog` 引导脚本。脚本负责现场解析引擎位置，顺序是
    `$WORK_LOG_BIN` → `<看板>/.worklogrc` → 板旁边的 `work_log.py` → 板旁边的 `scripts/`
    → 用户级安装位 → `$PATH`；全找不到就**退 70 并打印三条修法**，
    而不是抛一句语焉不详的报错。回归组 `[36]` 用「片段里不许出现
    `/Desktop/work-log-` 或 `.workbuddy/skills/work-log`」把这条钉死了。

  ★ **「只刷心跳不算在线」是 2026-09-30 凌晨加的那条 —— 它修的是一个"单向交流"的漏洞。**
    起因是用户实测的一句话：「两个 agent 都装上后……能交流吗」，答案是**不能**：
    片段只教了「怎么问别人」（`ask` / `reply` / `await`），没教「怎么被别人问到」。
    而响应式会话**没有后台轮询** —— 没人叫就不会醒，别人 `ask` 到你就是断的，
    **而且不报错**（这是最贵的一类坏：它安静得像一切正常）。
    所以片段现在必须给两样东西：**唤醒器入口**（`waker`，它退出 = 叫醒宿主）
    + **醒来第一件事**（`brief --peek` 查「待你回应」）。
    判据是结构性的、由 `[36]` 组锁住：扫到的每个片段里出现 `waker`，
    就必须同时出现 `--peek` 与「只刷心跳不算在线」这两句 —— 缺一即红。

      为什么唤醒器是「退出」而不是「常驻」：`waker` 到点自己退出，宿主醒来后重新挂上，
      在线靠的是**这个续期循环**，不是某个进程永不退出。常驻守护进程只会在机器重启、
      会话换目录时变成一只没人管的孤儿 —— 那就又回到了"以为自己在线"的老病。

  ★ 落点表也从 3 行扩到了 7 行 —— 因为「接入任何 agent」这句话的难点就在这张表上：
    **不同工具链读的启动文件根本不是同一个**，而这些差异没人记得住。
    按「换个目录开会话还认不认」分两档：`user` / `opencode-global` / `claude-global`
    是跨目录的（多 agent 场景优先），`repo` / `claude` / `gemini` / `cursor`
    只对在该目录启动的会话生效。第 ③ 坑就是当年那个真实事故：协议写进了
    只对某仓库生效的 `AGENTS.md`，而当事 agent 的 cwd 不在那儿 —— 它断了 42.4 小时。

    别名表只是**别名**，不是白名单：`--to <任意文件路径>` 一直可用。

  ★ 片段里还多了一条「名字要钉死」的说明。为什么值得占篇幅：`_get_agent` 按名字取的是
    *同一个 dict*。两个会话用同一个名字时，心跳 / `entries` / 未读游标 / `awaiting`
    全混在一起 —— 看门狗看到的是两个人交替刷新，于是**谁都不会被判卡死**，
    而板上完全看不出来。所以名字要么由 `$WORK_LOG_AGENT` 给会话钉死，
    要么用 `identity set` 按目录登记一次；**别把某个 agent 的名字写进共享文件**
    （`AGENTS.md` 会被任何在该目录启动的 agent 读到 —— 那等于给所有会话发同一个身份）。

      最后一行是它**故意不替你做**的那一步：落点判断仍要证据（对方到底读哪个文件）。
      猜错落点比不猜更糟 —— 那会产出一段看起来完备、却永远到不了对方手里的协议。

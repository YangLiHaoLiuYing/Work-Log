### 2026-09-30 命名批 · 多实例起名：让 agent 自己认领

> 同名多实例的老病：两个会话共用一个名字，last_seen / 游标 / 心跳预算全混在同一行，
> 板上**完全看不出来**。解法一直是"一实例一名字"，但起名靠人记 —— 这次把它交给工具。

#### Added
- **`claim [--base B] [--json]`**：锁内挑一个没人占的号码并**当场占座**（并发启动也拿不到同一个号），
  认领后是「待启动」，第一条心跳才点亮；同时写入 identity 表（本目录以后不传 `--agent` 也认得它）。
  - **框架名不写死**（用户追加拍板："万一人家叫 claudecode 呢"）：`--base` 缺省时**自动认宿主** ——
    优先 `$WORK_LOG_INSTANCE`（人显式给的），否则沿父链认工具名（opencode / claude / …），
    认不出退 **2** 让它显式给（`WORK_LOG_NO_INSTANCE=1` 可整体关掉探测）。名字宁可显式给，也不猜。
  - **同目录幂等**：重复认领拿到同一个名字 —— 重跑启动脚本不会每次冒新号。
  - **号码永不复用**（包括已离场的）：回收旧号码等于让一个带着陈年 last_seen 的名字复活、
    当场被判离线 —— 名字便宜，历史干净。
  - 占用面 = state 全部 ∪ 看板出现过的（手写路径也算）∪ 别的目录 identity 登记过的。
  - `--json` 吐 `{"name": …}` 给驱动层。

#### 自测
- 新增 `[33d]` 组 10 条（认领/幂等/递增/待启动不告警/--json/自动认宿主/认不出退 2/手写占用/结构性挑空号）。
  反向验证：把挑空号的循环改回写死 1 号，两个目录当场撞进同一个名字、断言变红。

### 2026-09-30 离场批 · 「问题是这些 agent 可能永远不会再次启动」

> 离线批把措辞分对了，但用户一针见血：对**确定永远不会回来**的 agent，「离线」什么都解决不了 ——
> 告警按 1h 退避上限**永远重复**（每只每天 ~24 条），板上永远挂着行，每条都在建议"等它回来"，
> 而它不会回来。猜（按时长分档）解决不了的事，需要人**拍板**。

#### Added
- **`retire --agent X [--note …] [--by …]`**：宣告「已离场」（状态第八档，最高优先级）——
  不再判卡死、不再发告警、它名下未确认告警一并确认（by `retire`）、挂起窗口与退避计数顺手清掉。
  对没出现过的名字退 **2**（不替你创建条目：静默创建会让拼错的名字永远挂在板上）。
- **复位必须便宜**：被宣告者自己 `post` 一条 ⇒ 离场标记**自动撤销**（post 当场提示
  「离场标记已自动复位」）；或显式 `retire --agent X --undo`。离场**不是删除**：state 条目原样留着。
- **全面跟进**：`status` 旗标 + 页脚「离线 N 个」汇总、`await` 把已离场对端判为「不会来了」（退 3）、
  `_peer_can_answer` / `brief` / `ask` 的等待警告、网页徽章（灰色 + 悬停提示 + 静默条中性灰）。
- **宣告后从人看的输出里直接消失**（用户拍板："都说了不会再启动，直接不要显示了"）：
  状态表 / 网页 / 看门狗 tick 行 / brief 汇总一律不再显示已离场者；
  数据层不删 —— `--json` 仍含它（state 已离场），`retire --undo` 与驱动层还要用；
  它 post 一条即自动复位、重新出现。

#### 自测
- 新增 `[33c]` 组：宣告 → 已离场且 `stale` 为空、`check` 退 0、不再产生新告警；
  post 自动复位；`--undo`；不存在的名字退 2；「已离场」全引擎只有一个推导点（结构性）。
  反向验证：把状态机的离场分支短路掉，「已离场」当场消失、行为断言变红。

### 2026-09-30 离线批 · 「明明 agent 进程都关了，怎么还在」

> 起因是用户的一张截图：网页徽章上四个 agent 红着「疑似卡死」、旁边挂着「补 hold」按钮，
> 而告警文案却说「判定为**离线**，不是卡死」。同一个事实两套说法 ——
> 规格早写了按**时长**分档（`protocol.md`：静默几分钟说「疑似卡死」，静默若干小时说「离线」，
> 两者处置动作**相反**），实现却在按 `alert_repeat ≥ 3`（报了几次，约 3–5 分钟）在告警正文里翻档，
> 且 `status` 状态表 / 网页徽章根本不知道「离线」这一档。

#### Fixed
- **「离线」升格为状态七档之一，判据全项目唯一**：模块级纯函数
  `agent_offline(silence, stale_after)` = `silence ≥ max(3600s, 20 × stale_after)`
  （1h 是"小时量级"的下限；20× 让阈值被调大的板跟着抬）。状态机在「疑似卡死」档内按它细分出
  「离线」子档；告警措辞翻档从 `alert_repeat ≥ 3` 改用它（退避间隔仍按报的次数算，两件事解耦）；
  `status` 状态表（`≤ 已离线` 旗标 + 页脚「离线 N 个」汇总）、`brief`、`ask` 的等待警告全部跟进。
- **离线不豁免心跳轴**：仍进 `stale`、仍告警、`check` 退出码不变 —— 工作可能真丢了。
- **网页徽章**：新增 `.st.离线` 灰色样式（不再灌红色）；静默条走中性灰；
  悬停提示写明处置（等它自己 post 回来，或替它收尾并 ack）；
  **离线行不再显示「补 hold」按钮**（hold 是给还活着的线声明用的，救一个不存在的进程没意义）。

#### 自测
- 新增 `[33b]` 组：`agent_offline` 纯函数边界（1h 下限 / 20× 阈值两侧各验）+
  「三处一致」行为断言（伪造静默 9999s 后，`status` / `check` / `alerts.md` 都说离线、
  且不再出现「疑似卡死」措辞）+ 结构性断言（状态机与告警两个调用点都走 `agent_offline`）。
- `[9]`/`[28]` 组既有断言改判「离线」（夹具静默 2.8h / 26 年，早已过 1h 分界）；
  `[9]` 组 `backdate()` 夹具连**日期段**一起改老 —— 否则静默随"今天几点跑"漂移，
  断言会在每天午夜后一小时左右翻车。

### 2026-09-30 片段批 · 被写进别人启动文件的那段协议，漏了 `await` 的第 4 个出口

> 起因：给第 8 代同步 `preview` 时，拿第 2 幕里那句「双方都已各认出这条真死锁并**收手退出**
> （`await` 退 **5**）」去核对三处文档，发现骨架上都对 —— `SKILL.md` 的退出码铁律表写着
> `5`、`references/protocol.md` 的完整表写着 `5`、`[43]` 组还断言了 `5` ——
> **唯独 `onboard` 吐出来的那段片段没写**。

#### Fixed
- **★ `onboard` 片段只教了 `await` 的 3 个出口（`0`/`1`/`3`），漏掉 `5`=互相等待。**
  片段原话是一个**封闭枚举**：「…**3**=对方已收工（别等了）。**这三个码**就是为了区分
  「再等等」和「别等了」」。而契约早已是 4 个出口，且 `5` 的处置**与 `1` 正好相反** ——
  `1` 是「对方活着但没答」⇒ 再等等 / 催 / 换人问；`5` 是「你在等的人正在等你」⇒ **先回答它**。
  这一条比一般文档错更贵，因为**这段片段是会被写进别的 agent 启动文件的**
  （`onboard --to user` / `opencode-global` / `repo` …），它往往是新 agent 唯一读到的协议。
  照片段接进来的 agent 拿到 `5` 时，最轻是当成未知错误、最坏是**当成超时去干等** ——
  而这两种都**不报错**。形态上它属于"开药的那一份与验药的那一份不是同一份"：
  `doctor` 验不出它，`onboard` 也只管开，谁也不负责核对两边讲的是不是同一件事。
- **改后**：那一行变成 4 个出口，并补一句处置差异（明说「`5` 与 `1` 相反」）。
  同时**重新捕获** `examples/onboard-output.txt`（沿用 `doctor` 那份的隔离捕获法：
  `HOME` 指到临时目录、在映射成 `<会话工作目录>` 的 cwd 里真跑一次），
  `docs/preview.html` 第六幕的内嵌片段一并同步 —— 三处口径保持一致。
  `SKILL.md` / `references/` 一个字没动（它们本来就是对的）。

#### 自测（58 组 656 条，0 失败）
- **断言条数不变，而且这条改动本来就不在任何护栏的覆盖面上。**
  `[36]` 锁的是片段的**结构**性质（不许出现引擎本机路径、必须给 `waker` + `--peek` +
  「只刷心跳不算在线」），`[35]` 锁的是「开药必须能过 `doctor ③`」。
  一个**漏讲的出口**既不会让它们变红、也不会让它们变绿 ——
  **这正是它能长期躺在那里没人发现的原因**，也是它值得写进 CHANGELOG 的原因。
- 三处验收（skill 目录 / 发布包布局 / 发布包布局 + Python 3.9.6）各自全绿。
- 顺带核实：`5` 在 `SKILL.md` 铁律表、`references/protocol.md` 完整表、`scripts/selftest.sh`
  的 `[43]` 组三处**都在**，缺的只有 `onboard` 片段这一处 —— 是遗漏，不是口径分歧。

#### Added
- **`check` 的第二根轴：办事轴（"该办的事还在不在"）。** 心跳轴问「它还在吗」，

  首字节吞进变量名致**整个脚本 rc=127 横死**。让文本走文件 = 让判据只面对字节，

#### Added
- **`scripts/waker.sh`：外部唤醒器 —— 让"保持在线"变成可验证的机制，而不是口头承诺。**
  响应式会话（WorkBuddy / CLI/TUI）没有被唤醒就不能自己醒来，所以「保持在线」是**三段**：
  `hold` 不收工 + 唤醒即读（`read-user`）+ 一个外部进程盯着板、有冲你来的事就**退出**
  以唤醒宿主。三条边界都真跑验证过：①**不替任何 agent 回话**（只退出，否则会与别人的
  listener 抢同一条喊话、产生重复回执）；②窗口要续期（默认 45 分钟，退出后由宿主重启）；
  ③用法错误一律退 `2`。实测在真板上被叫醒 4 次（用户消息 8→9、11→12，以及 `ask` 路径），
  每次循环 `read-user` → 回执 → 重启唤醒器。
- **`scripts/ask_listener.sh`**（由板上的另一个 agent 提供）：把「有人 `ask` 我」也变成可自动
  应答的事件 —— 常驻 bot 的唤醒 prompt 里缺 `brief`，导致定向问答对它是**断的且不报错**
  （实测：`ask` 到 listener 的 bot 等满 120s 退 `1`）。
- **`ack-user` 认领去重（先到先得）**：别人已认领 ⇒ 退 **`3`**（"已被别人处置"这一族，

### 2026-09-28 · 看板交互修复 + 告警可处置化 + 人数/阈值不再写死 + 同名多实例识别 + 宿主识别可扩展 + 历史可归档

> 「疑似卡死」，告警刷到 1800+ 条，而它其实只是在跑长任务没声明；
> 右上角「协作：1/2 在干活」的分数式呈现也被质疑「怎么可能只有两个 agent 干活，
> 大部分情况都是好几个，且不确定」。

#### Fixed
- **看板输入框：中文/日文输入法按回车选字会把拼音当场发出去。** 三重防护：
  `isComposing` / `keyCode 229` / `compositionend` 后 80ms 窗口（部分浏览器在
  compositionend 之后仍补发一个 `isComposing=false` 的回车）。`/` 聚焦快捷键同样加保护。
- **告警不可处置**：告警只说「疑似卡死」，收到的人不知道该干什么，往往只补一条心跳
  ——过 90s 又被报一次，反复刷屏（实测 1800+ 条）。现在告警文案**自带补救命令**
  （`hold --agent <名字>`）并明确要求先分清「真卡死」与「在跑长任务没声明」。
- **自动界面起的看门狗不继承卡死阈值（真缺陷）。** `post` 发现"还有别人在干活"时会
  自动起一个 `serve` 并弹浏览器，这只 serve **用户在提示行里看不见细节**，而它原来
  **写死用内置 45s** —— 于是「我明明用 `--stale-after 90` 起的 serve」是句空话，真 LLM
  agent 单轮 30~120s 必然被它误报。实测：手动起了 8899/999s，`post` 又偷偷起了
  8790/45s，四条「疑似卡死」全是那只隐藏看门狗报的。现在 **`init --stale-after N`
  或 `WORK_LOG_STALE_AFTER=N` 声明一次，所有看门狗都听**，且自动启动的提示行会把
  这只看门狗的阈值打出来（`…；卡死阈值 90s；停止：kill N`）。
- **同一个阈值问题在「手起的那只」上也存在。** 上面只修了自动界面起的那只；
  `serve` / `watch` / `check` 的 `--stale-after` 默认值仍然是写死的常量 45，
  会把板里声明过的 90 悄悄压掉。现在**统一解析**：
  `显式参数 > $WORK_LOG_STALE_AFTER > 板上 init --stale-after 声明 > 内置 45`
  （各子命令的 argparse 默认值刻意改成 `None`，就是为了让"没人显式写过"不再等于"用 45"）。
  另修：`board.md` 板头那句「静默超过 Xs」原来写死 45，声明 90 后板头仍在说谎 ——
  现在会同步成本板实际阈值（只改那一行，不动任何日志内容）。
- **5 个 CLI 选项漏登记进 `KNOWN_OPTS`**（`--any` `--as` `--collab-min` `--report`
  `--timeout`）：`--text --timeout` 这种「漏传值」会被静默当成正文，用法错误伪装成内容。
  补登记之外，加了**结构性护栏**——直接从 argparse 把全部选项拉出来和名单对账，
  以后再加选项忘了登记，自测当场红。
- **实例锚点乱跳 ⇒ 把同一个会话报成多个实例（误报，已修）。** 两个独立根因叠在一起：
  ① 「像 agent 宿主」的判据原来是**对整条命令行做子串匹配**，而实测有程序把**整块环境
  变量 JSON 当参数传**（里面就有 `CLAUDE_PLUGIN_ROOT`）⇒ **宿主自己被认成 claude**；
  ② `detect_instance()` 里 `pid = ppid` 之后才用**上一行**的启动时刻拼字符串，返回的是
  「父进程的 pid + 子进程的启动时刻」这个**根本不存在**的组合 ⇒ 锚点挂在一个随时重启的
  辅助进程上，同一个会话每探测一次就换一个标识。现在：只看 **argv 的可执行名**
  （对"跑脚本的进程"会去 **argv[1]** 找真身：`node …/claude-code/cli.js`、
  以及 macOS 上 shebang 脚本被 `ps` 显示成 `/bin/sh /路径/opencode …` 这两种）、
  **`-c`/`-e` 这类开关不算路径一律跳过**（agent 起我们常是
  `bash -c "… --text 'opencode 卡住了' …"`，argv 里就带关键词，认它等于每次都换锚点），
  且**重新读父进程自己那一行**，pid 与启动时刻必定来自同一个进程。
  另：`ps` 取启动时刻强制 `LC_ALL=C` —— `lstart` 的月份按 locale 渲染，用户 `LANG` 一变
  会把同一个进程算成两个实例。
  实测：真看板上那两条 `workbuddy` 实例是误报，已清掉并留痕更正。
- **实例探测又补两个漏网（同一天第三、四修）—— 起因是用户问「我起别的 agent 能识别吗，
  比如 Hermes、Claude Code、Kimi Code」：**
  ① **shebang 脚本的真身在 argv[1]。** macOS 上带 shebang 的脚本，`ps` 显示的是
  `/bin/sh /路径/opencode …`（argv[0] 是 `sh`）。只认 argv[0] 会**漏掉真实宿主** ——
  实测 `hermes` 正是这种：`~/.local/bin/hermes` 是 4 行包装、`exec` 掉自己，
  真身是 `…/venv/bin/python …/hermes-agent/hermes`。现在对 shell / 解释器两类都去
  argv[1] 找真身，但 `-c`/`-e` 开关不算路径、一律跳过（否则又会把一次性 shell 认成宿主）。
  ② **锚点要查死活。** 宿主重启（关掉再开一个、或 `someagent run "…"` 这种"一次一个进程"
  的用法）会让旧锚点一直留在 state 里，下一次 post 就被读成"又多了一个实例"
  ⇒ **满屏假的多实例告警**。现在锚点会查宿主进程还在不在（pid 不在、或那个 pid 已被
  系统**复用**给别人）⇒ 那不是并发实例，是同一个会话换了宿主 ⇒ **静默替换，不告警**。

  任何 macOS App 都覆盖得到）。那种是「**一个进程承载多个会话**」，硬认会把几个会话
  算成**同一个**实例 —— 那是"看起来正常，其实在撒谎"。Hermes 桌面版就属于这种（按设计不认）。
- 候选宿主必须**活够 20 秒**才敢当锚点：刚起的短命进程锚上去，标识下次就变了。
  （测不出年龄时不拒绝 —— 不要拿"测不出来"当拒绝理由。）
- **`prune`：把过老的历史搬进 `archive/`（新子命令）。** 起因是量了一下真看板的体积：
  `board.md` 607KB / 2606 行、`alerts.md` 400KB / 2001 条、`state.json` 89KB（其中
  `alerts` 一项 47KB）。三份文件全都**只增不减**，`doctor ⑤` 会报出噪音比却**没有任何手段处置**。
  三条规则：① `state.alerts` 里**已确认**且超过 `--days` 天的整条丢掉、超过 1 天的把长正文截短

  200/200 条都带 `→`，正文平均 188 → 69 字节）；**未确认的永不触碰**（那是待办）。
  ② `alerts.md` 只留最近 `--keep-alerts-md` 条，其余搬走。③ `board.md` 搬走 `--days` 天之前的
  **整段日期块**（最后一段无论如何留着）。

- **`prune` 里两条必须成立的不变量**（写它的时候当场撞出来的，都补了回归）：

    ⇒ `entries[2578:]` 恒为空 ⇒ **那个 agent 从此静默收不到任何新动态**（`brief` 只会说

## [0.7.0] — 2026-09-25 · 固定 agent 名字 + 换台电脑也能用

主题：`0.6.0` 把「接入」补齐了两端（`onboard` 交付、`doctor` 自查），但**接进来之后**还有两类
失效会在**没有任何人报错**的情况下发生 —— 而它们恰好都发生在"看起来一切正常"的时候：

- **名字撞了。** `_get_agent(st, name, t)` 按名字取的是 `st["agents"][name]` —— **同一个 dict**。
  两个会话叫同一个名字时，它们共享 `last_seen` / `entries` / `board_cursor` / `user_cursor` /
  `awaiting`。后果不是"名字不好看"：看门狗看到的是**两个人交替刷新**，于是**谁都不会被判卡死**；
  `entries` 是两个人的合计，「待启动 / 从未写过心跳」判据失效；`awaiting` 被后写的人覆盖，
  等待图画出错的边。**而板上完全看不出来。** 这是整套判断（谁卡死、谁在等谁）唯一的地基。
- **换了机器。** 接入片段是要**离开这台机器**的（抄进对方的记忆文件、拷到别的电脑）。
  它以前写死 `工具路径：/Users/<某人>/…/work_log.py` —— 到了第二台机器上就是一条**死链**，
  而且失效是静默的：对方照抄、报个"文件不存在"，然后**不再报到**。
  也就是 `0.6.0` 主题里那次事故的复现路径。

顺带把「落点」这一步从**人工**改成**观测**（`onboard --detect` / `--to auto`）：
上一版说「落点只能靠看对方二进制的证据」—— 那句话对，但它把「要靠证据」
错说成了「要靠人去查」。装过的工具链一定留下痕迹，所以这是可观测的。

- **★ 约数波浪号被当成路径 ⇒ `doctor` 退 `70`，并且顺手埋了一种静默假绿。**
  中文行文里的 `~90%` / `~2.4s` / `~0.9-3s`（**约数**）被 `_PATH_TOKEN_RE` 的裸 `~` 分支
  吃成路径 token，而它展不开（`Path("~90%").expanduser()` 抛 `RuntimeError` ——
  **不是** `OSError`，所以 `except OSError` 接不住）。两个后果，第二个才是要命的：

  - 异常没被接住 ⇒ 一路冒到 `main()` 变成 **`70`（内部错误）**。真机

    于是 `doctor` 整条炸掉 —— 一个约数把体检打成"工具坏了"。
  - 只吞异常**更坏**：展不开会**原样保留**，`resolve()` 把它当**相对路径**接到 cwd 上，
    变成 `<cwd>/~90%`；**板恰好建在当前目录**时与板前缀匹配 ⇒
    一句「延迟 ~2.4s」就把这份记忆判成"提到了本板"。那正是 `_literal_forms()` 注释里
    立誓要避免的「永远为真的废话」，而且**不报错**。

  A/B 反证（同一段文本、板 = cwd）：

  | 实现 | `_mentions_board` 的结果 |
  |---|---|
  | 修复前（裸 `~` 正则 + 不接异常） | 抛 `RuntimeError` ⇒ CLI 退 **`70`** |
  | 只吞异常、不检查"展开后是否绝对" | **`True`** ⇒ `doctor` 判「✓ 1 处齐备」并退 `0`（假绿） |
  | 现在 | `False` ⇒ 判「⚠ 只提到工具」并退 `1` |

  修法不是给约数加特例，而是把"这看起来**确实**像个路径"变成**硬前提**，两层都要：

  ① `_PATH_TOKEN_RE` 的 `~` 分支要求**后面就跟分隔符**（`~/x` 或 `~用户名/x`）——
  裸 `~`（板恰好在家目录）刻意**不认**：判据宁可漏、不可猜；
  ② 新增 `_expand()`：展不开返回 `None`（**不原样保留**），且判据只接受**绝对**结果 ——
  「`resolve()` 把相对路径接到 cwd 上」正是假阳性的根源。

## [0.6.0] — 2026-09-24 · 把「接入」补齐两端：生成端 `onboard` + 自查端 `doctor` + 告警退避

主题：这套工具**最讽刺的一种失效**不是引擎坏了，而是协议从来没到过某个 agent 手里 ——
板建好了、`serve` 起上了、协议也写进了**对方**仓库的 `AGENTS.md`，然后自己**断了 42 小时心跳**。
根因是 `AGENTS.md` **只对在该仓库启动的会话生效**，cwd 在别处的 agent 永远读不到它；
而写协议的人自己在同一份文件里就写了「workbuddy 的 skill/记忆不在本仓库里」——
**知道洞在哪，却把协议写在了洞的另一侧。**

后来发现这条战线上「接入」其实是**两件**事，而它们的自动化程度**恰好相反**：

- **机械接入（工具侧）本来就是自动的。** `post` 对未知 agent 名会**当场注册**（`_get_agent`），
  根本没有 `join` 子命令；它那一次心跳让 `others` 非空，顺带触发 `auto_ui`
  （起 `serve` + 弹浏览器，而 `serve` 默认自带看门狗）。**这一半不需要改任何东西。**
- **认知接入（它那侧）不可能自动。** 模型没有推送通道 —— 上下文只在它**自己**发起工具调用时
  才更新。唯一办法是让义务句落进它**启动时一定会读到**的文件里。

所以本版本补的是**交付那一段**：`doctor` 负责「我有没有被拉起来」，`onboard` 负责
「把该报什么名、往哪报、多久报一次，写成一段能直接粘贴的协议」。
**两端共用同一道门槛**（`_path_forms()`），这样才不会出现「自己开的药、自己验不过」。

### Added

- **`onboard` 子命令 —— 把「接入片段」交到第二个 agent 手里。** 默认**只打印不落盘**
  （连看板目录都不会顺手建出来：该命令的 `--dir` 解析走新增的 `resolve_dir(..., mkdir=False)`，
  否则一个号称 dry-run 的命令会顺手 mkdir，那就不叫 dry-run 了）。
  `--to user|repo|claude|<路径>` 才写，写之前先备份、失败即中止（不留半个改动的文件）。
  - **幂等**：内容包在 `<!-- work-log:begin -->` … `<!-- work-log:end -->` 之间，
    重复跑只替换块内、块外一字不动 —— 所以它可以反复跑，也能跟着仓库进版本库。
  - **拒绝覆盖手写协议**：目标里已有「指向本板的异己协议」时**默认拒绝并退 `2`**，
    要追加必须显式 `--force`（两份互相打架的协议比不做更糟）。
    - ⚠️ 判据**不能**只认字面量 `work-log`：自测 `[35]` 抓到的真洞 ——
      实测手写的那份只写了「看板：`<路径>`」，**压根没提工具名**，只查工具名会把它静默追加成两份。
      现在改成「给了本板坐标（`_path_forms`）**或**提过工具名」。
  - **它产出的片段必然能通过 `doctor ③`** —— 片段天生带「坐标 + 报到义务」，
    且与 `doctor` 共用同一道门槛。这是刻意设计：**开药与验药必须用同一把尺**。
    回归组 `[35]` 把这条钉住了，并配**反向对照**（把坐标留下、拿掉义务句 ⇒ 那个 ✓ 必须立刻掉下来），
    以证明那个绿不是碰巧为真。断言 307 → **325**（+18）。
  - 刻意**不做**「自动发现对方是谁、它读哪个文件」—— 那要靠翻对方二进制里的字符串（`SKILL.md` 那一步）。
    **猜错落点比不猜更糟**：它会产出一段看起来完备、却永远到不了对方手里的协议，
    也就是本版本主题里那次失效。命令只承诺一件事：给我一个落点，我给你一段一定验得过的协议。
  - 备份内容直接用**已经读进内存的原文**写回，不再多引一个模块去 copy：
    本工具零依赖那条断言（`[18]` 白名单）是真护栏，不为了省事放宽；顺带也消掉了读盘与备份之间的 TOCTOU 窗口。

- **`doctor` 子命令 —— 把「接入 4 步」对称地用在自己身上。** 只读，五项体检：
  ① 同一项目有没有第二块（废）看板；② 当前 cwd 有没有指令文件；③ **每会话被注入的记忆文件里
  有没有这块板的坐标**（这条才是决定性的）；④ 板上各人的 `last_seen`（把「我」单独标出来）；
  ⑤ 告警 ÷ 实质发言的比值（远大于 1 ⇒ 真信号已被噪音埋掉）。
  退出码与协议一致：**有病 `1`**，板不存在（用法问题）`2`，不伪装成业务码。
  - ③ 的匹配刻意**不**用 `/.workbuddy/work-log` 这种尾巴 —— 那会命中任何一块板，
    使「我有坐标」变成一句永远为真的废话；改为认本板的两种书写形态（绝对路径 / `~/…`）。
  - ③ 的判据随后**又收紧一档**（同日追加）：不再只查"记忆里有没有本板坐标"，而是
    **坐标 + 报到义务 + 落点层级**三层（`DUTY_MARKERS` / `_is_global_mem`）。
    起因是一个**实测到的洞**：坐标写进了用户级记忆、**义务句却只写在项目级**
    ⇒ 换个工作区开新会话就断；而只查坐标的旧判据照样判 ✓ —— **判据自己看不见这个洞**，
    这比洞本身更值得记。断言 304 → **307**。
    - 「跨工作区那份里没有它」刻意**不**计 `bad`（当前工作区确实连得上，不算现在就失效），
      但必须把警示打出来，并由 selftest 断言那行文字存在 —— 否则它就只是装饰。
    - `DUTY_MARKERS` 刻意**不收**「报到」这类词：它太容易出现在**诊断句**里
      （"我这条线没有在报到"），会把"有病"判成"有义务"。**假阴性可以接受，假阳性不行。**
  - ① 的判据也不能只看目录名：废板的目录名取的是**当时那个 cwd 的 basename**，
    与现在的板常常不同（实测：桌面那块板目录名与活板 cwd 的 basename 完全不同）。
    所以先比 `cwd`，再退一步比「板上是不是同一批人」。

### Changed

- **告警退避（P0 噪音治理）。** 原先只看 `alert_open` 就永远按 `COOLDOWN` 重复，
  实测某板 42 小时攒出 **994 行 watchdog vs 110 行实质发言** —— 「另一个 agent 真的停了」
  这件事被彻底淹没。现在连续重复 `ALERT_BACKOFF_AFTER(3)` 次后按 `135s × 2^k` 退避
  （上限 `3600s`）：**同一场景从 ~1120 条降到 ~45 条**。
  - 退避基数**刻意与 `--cooldown` 解耦**（只取 `max`）：否则有人把 cooldown 调成 0，
    就等于把退避也一起关掉了。
  - 措辞分档：静默 2 分钟说「疑似卡死」（值得去救），静默数小时说「**离线**」（人已经不在了）。
    两者处置动作相反，共用一句话会让人去救一个不存在的进程。
  - 新增 `fmt_dur()`：告警里的时长从 `152778s` 变成 `42h30m` —— 静默时长正是选处置动作的依据，必须可读。
  - 恢复心跳时 `alert_repeat` 一并归零，否则它下次静默会直接从「离线」档开始。

### Fixed

- **`check_stdlib_only.py` 把自己崩成了「发现违规」。** 它的 `TARGETS` 是相对 cwd 的路径，
  换个目录调用就抛 `FileNotFoundError`，而解释器此时恰好退 **1** —— 与「真的引入了 `requests`」
  长得一模一样（一边假违规，一边真违规被淹没）。现在包根按**脚本自身位置**推断，
  任意 cwd 都能跑；找不到文件 / 解析失败改退 **2**，并明说「这是检查器自己没跑起来」。
  顺带：这是本项目「工具跑不起来，绝不该伪装成业务结论」那条铁律的第 N 次复现。

- **`examples/demo.sh` 会留下"孤儿"serve 与临时目录 —— 也就是「跑完自动清理、不留痕迹」是假的。**
  两个独立缺陷叠在一起：
  ① 四处 `init` 都没带 `--no-auto-ui` ⇒「板上第 2 个 agent 上线」会**自己起一个后台 `serve` 并弹浏览器**，
  而 `cleanup()` 只杀它自己记下的 PID，那些 `serve` 全留下；
  ② 场景 ② 的两个后台 `await` 写成了 `run ... &` —— `run` 是函数，`&` 起的是一个**子 shell**，
  `$!` 拿到的是那个子 shell 的 PID，`kill $!` **杀不到真正的 python**；它变成孤儿跑满 30s timeout，
  在本脚本结束**之后**把刚删掉的 `deadlock/` 又写回来。
  实测清出 **3 个跑了 1 天 20 小时的残留 serve**（占着 8787/8789/8790）+ 若干只剩 `deadlock/` 的临时目录。
  修法：`init` 一律带 `--no-auto-ui`；后台调用去掉 `run` 包装让 `$!` 指向真进程；`cleanup()` 增加
  `pkill -f "$TMP"` 兜底（**必须判非空** —— `pkill -f ""` 会匹配所有进程）。
  **验证**：清空残留后从 0 跑一次 demo，跑前 / 跑后均为 **0 个残留目录 + 1 个 serve**。

## [0.4.0] — 2026-09-19 · 把预算从"互相客套"里救回来

### Added
- **通信熔断（乒乓）**：同一对 agent **连续交替**来回（同一个人连发两条不算一轮）
  达 `6` 轮开始提醒，达 `12` 轮 `ask`/`reply` 直接拒绝写入（退出码 `4`），`--force` 可覆盖。
  非交替的批量对话不会被误判。
- **心跳预算**：单个 agent 每分钟 `post` 上限（`init --rate-cap`，默认 60，`0` 关闭）。
  超线拒绝写入（退出码 `4`），且**不刷新 `last_seen`** ——
  于是「刷屏刷到卡死」的 agent 会同时被熔断和看门狗各抓一次，而不是靠刷屏续命。
- **多路等待**：`await --id 1,2,3`（默认全部必须回）+ `--any`（任一回应即达成）。
  未达成者**全部已收工**时退 `3`，并打印已拿到的答复与还缺谁。

### Changed
- `--id 0` 被**彻底拒绝**（退出码 `2`）。它曾经是「等任何新动态」的合法写法，
  但编号一丢就变成静默假成功。想要那个语义就**不写 `--id`**。
- `await` 的三个出口语义冻结：`0` 拿到 / `1` 超时 / `3` 对方已收工。

### Fixed
- **内部异常不再伪装成业务结论。** 新增退出码 `70`（sysexits `EX_SOFTWARE`）：
  引擎自己崩了必须与「对方没回」分开，否则调用方会拿一个软件 bug 去下业务结论。
  （起因：一次改动残留变量名导致每次 `await` 都崩，而崩了返 `1`，症状看起来像"对方全都没答"。）

## 契约冻结说明

以下内容在 `0.x` 期间也**不会**做不兼容变更：

- **退出码语义**：`0` 成功 / `1` 业务（超时、有卡死或险情）/ `2` 用法错误 /
  `3` 对端已收工、抢锁冲突 / `4` 熔断 / `70` 工具自身 bug
- **看板行文法**：`<agent> HH:MM:SS [标签] 正文` 与 `## YYYY-MM-DD` 日期分节
  （这是历史看板能被反解的前提）
- **三个 CLI 入口的相对位置**：`scripts/work_log.py`、`scripts/selftest.sh`、`SKILL.md`

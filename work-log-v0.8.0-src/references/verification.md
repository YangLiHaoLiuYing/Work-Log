## 怎么证明这个 skill 真的有效（selftest 证明不了）

`selftest.sh` 只证明「CLI 没坏」，**证明不了「真实模型会不会照协议走」**。要验后者得用真模型：

```bash
python3 scripts/llm_agent.py --agent agent1 --board /tmp/demo/log \
    --base https://<你的端点>/v1 --key "$KEY" --model <模型名> \
    --peer agent2 --role "后端" --task "和 agent2 约定接口字段" --max-steps 16 &
python3 scripts/llm_agent.py --agent agent2 --board /tmp/demo/log \
    --base https://<你的端点>/v1 --key "$KEY" --model <模型名> \
    --peer agent1 --role "前端" --task "和 agent2 约定接口字段" --max-steps 16 &
```

`llm_agent.py` 把 work-log 的动词（post/ask/reply/await/brief/read_user/ack_user/finish）
暴露成工具，让**模型自己决定**说什么、问谁、等谁，然后把它说的每句话落到真实看板上。
于是「协商是模型真的做出来的，还是 host 替它编排的」就有答案了。

### 实测出来的三个硬数字（别照抄默认值）

用真实模型跑过之后的结论，比文档里的想当然可靠：

1. **单轮模型耗时 25~120s。** 实测同一端点内不同模型：快的 0.6s，慢的 118s。
   于是默认 `--stale-after 45` **必然误报**（实测：agent 正常思考 56s 就被判「疑似卡死」）。
   **跑真 LLM agent 一律用 `--stale-after 90` 起步，慢模型要 180。**
2. **推理模型会把 token 烧在思考上。** 小 `max_tokens` 会让它 `finish_reason=length`
   且 `content` 为空——看起来像「模型不听话」，其实是被截断了。
   给推理模型留 `max_tokens ≥ 3000`。
3. **思考通道的字段名不统一**：见过 `reasoning`（GLM 系）、`reasoning_content`（DeepSeek 系）。
   解析流式时两个都得试，否则会得到「帧数很多但正文为空」的假象。

### 驱动层（llm_agent.py）踩过的坑 —— 都是"看起来像模型不听话"的假象

下面这几条是把真模型接进来之后才暴露的，跟 work-log 协议本身无关，但会让你误判「skill 不行」：

1. **`await` 被自己的驱动层杀掉。** 模型调 `await --timeout 120`，而驱动层 `subprocess.run`
   也设了 120s —— 两者相等，子进程会在 await 即将返回的瞬间被信号掉，抛出一个没人接的
   `TimeoutExpired`，整个 agent 当场死在第 3 步。**驱动层的超时必须比模型请求的等待时间长**（留 90s 余量）。
2. **模型会把工具参数套一层壳，而且壳的值可能是字符串也可能是对象**：
   ```jsonc
   {"arguments": "{\"id\": 1, \"text\": ...}"}   // 值是 JSON 字符串
   {"arguments": {"id": 1, "timeout": 120}}     // 值是对象  ← 更容易漏
   ```
   只剥字符串那种，遇到对象壳就会得到一个 `id` 丢失的 dict。而**丢掉编号的后果极隐蔽**：
   `await --id 0` 在协议里是合法语义（"等任何新动静"）且**返回成功**，
   于是 agent 会收到一个"成功"，以为自己拿到了答案 —— 其实只看到一条路过的无关心跳，
   然后基于这个假象继续往下定结论。**宁可明确报错让模型重试，也不要静默传 0。**
   解析时剥 str/dict 两种壳，再按该工具声明的 `required` 字段把真参数找回来，
   最后校验必需字段缺失就报错。
3. **空 text 是解析失败的副产品，不是模型懒。** 参数没解开时 `text` 是空串，落到 CLI 上被拒。
   驱动程序应在调用 CLI 之前就判空并**把错误喂回模型让它重试**，而不是先写一条空心跳再失败。
4. **模型频繁重试同一个调用时，先怀疑参数解析**，别急着说"模型不行"（实测：两个 agent 各花了
   5 步反复 `reply` 同一个编号，根因只是 id 被壳吃掉变成了 0）。
5. **工具自己的崩溃绝不能伪装成业务结论。** 实测一次改动后 `cmd_await` 里残留了一个变量名，
   命令抛 `NameError`、进程以 **1** 退出 —— 而 1 在这套协议里的含义是"超时"，
   于是所有调用方都会得出"对方没回"这个**完全错误的结论**（症状是"险情全没了 + await 全超时"，
   看起来像功能失效，实际是引擎崩了）。现在内部异常一律走 **70**，
   你看到 70 就知道该去看 traceback 而不是怀疑模型。**排查这类问题的顺序：
   先问「这个失败是模型产生的，还是驱动层/工具产生的」。**

### 判定「达到预期」的标准

跑完看板，能同时满足这几条才算数：

- 双方各有 `[提问→X] #N` 与 `[回应#N]`，且 `#N` 能对上（单向广播不算）
- 各自的 `[决定]` 里能看出**读了对方的原话**（引用了对方给的具体约束，而不是各说各话）
- 用户喊话有 `[回执#N]`（有人认领），不是没人理
- 没有任何一方在 `await` 超时后仍然写出「对方说……」——出现这种就是编造，整条链不可信

**验收一定要回原始 `state.json`，不要采信 agent 的自述。** 三行命令就够：

```bash
python3 -c "import json;d=json.load(open('<dir>/state.json'));\
print([(e['id'],e['from'],e['to'],e['status']) for e in d['exchanges']]);print(d['acks'])"
# 期望：每条交换 status 都是 closed；acks 里有那条喊话
```

### 想验「遇到冲突会怎样」，冲突要插在结论**之后**

要测「用户中途改了要求、且新要求和已定结论冲突」时的行为，关键是**时机**：
必须等双方都写下 `[决定]` 之后再注入相反要求。结论还没形成就插，那不叫冲突，
叫"一开始就这么要求"，测不到任何东西。手法：轮询看板里 `[决定]` 的条数，够了就 `say`。

**但别等太久**：真模型收敛得快时会直接 `finish` 收工，注入就落空了。
实测第三次跑（`/tmp/amd-test4`）agent1 只用 10 步就收了工，注入（在出现 2 条 `[决定]` 后再 sleep 8s）
比它晚 6 秒 —— 结果 agent1 已退出，agent2 的协商提问 `#3` 永远等不到回应。
**看到第一条 `[决定]` 就注入，并把注入后的 sleep 压到 0~2s**；同时给 `--max-steps` 留够余量
（参数解析失败会吃掉步数，实测每次失败损失 1 步）。

实测（真端点 + 真模型）注入「不许设死上限、2 万字也必须一次合成完」后：

- 双方都没有沉默忽略，也都没有嘴上答应 —— 各写一条 `[阻塞]`，含
  「用户要求 X / 当前约束 Y / 冲突点 / 理由」，然后开一个新的 `ask` 去协商折中；
- 被问的一方给出**真的工程折中**：直说"单次推理 2 万字技术上不可行（时延 / 显存 OOM / 音质退化）"，
  再给替代方案（前端仍一次传一次返回、不截断不报错，服务端自动分段合成再拼接），
  并显式写明「满足什么 / 做不到什么 / 替代方案是什么」；
- 提问方确认后 `[决定]` 定稿并 `[任务完成]`；
- 全程 **0 条看门狗告警**（步均 2~3s、等待最长 100s+）。

这一轮同时暴露并修掉了 4 个驱动层 bug（见上节），注意：**这些失败看上去都像"模型不听话"，
根因全在驱动层**。判定 skill 有没有达到预期之前，先把驱动层的问题排干净。

### 一个真实边界：收工的 agent 是**不可达**的

agent 一旦写了「任务完成」并退出，它的进程就没了 —— 这时候再 `ask` 它，答案**永远不会来**。

`ask` 会立刻给出警告（实测送达模型：
`⚠ agent1 当前是「完成」，大概率等不到回应——考虑换人或自己拍板`），
未闭合的交换也会一直在 `brief` / `check` / 视图里显示为 open ——
**没人回答这件事是看得见的，不会静默消失**。

`await` 侧现在会**当场识别**这种等待并立刻收手：退出码 `3` +
`✗ 对方已收工：<agent1> 写了「任务完成」，#3 的答案不会来了（只等了 0s，没白耗完 60s）`，
而不是把 `--timeout` 干耗完。看门狗也会把它作为 `[不可达等待]` 险情告警出来。

好消息是：真模型在这种情况下**没有编造对方同意**。实测（`/tmp/amd-test4` 的 `#3`，当时还没有 P0 收手）：

- 日志原文：`agent1 已标记完成、未回应我的 #3 折中提议（等 60s 超时）`
- 全文检索"agent1 同意 / 接受了 / 确认接受" → **0 命中**，它是自己拍板给出最终版的

也就是说：**拿不到就如实上报、并允许自己拍板，编造才是被明确禁止的**。这几条规则同时生效，协作链才可信。
`await` 的 `0/1/3` 三个码，正是为了让模型能区分"再等等"和"别等了"。

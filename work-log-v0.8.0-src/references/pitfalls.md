# 踩坑清单（完整版）

> 什么时候读它：正文那份简表不够用时 —— 这里每条都带现场与后果。

## 坑

- **驱动层不许在脚本里复刻引擎的判据，计数/解析一律问引擎**（2026-09-29 实测，两处独立踩到同一类根因）。
  判据写在文档里 ≠ 脚本里长对了。本机两处都栽在同一件事上：数「用户喊话条数」。
  引擎 `parse_user` 把每个**非空、非 `#`、非 `>`** 的行都算一条（文档明说可以写纯文本），
  而两处脚本各自复刻了更严的规则：监听器用 `grep -cvE '^(#|>)'`（把空行也数进去），
  唤醒器用 `'^[0-9:]+ 用户：'` 前缀正则（用户不写前缀就永远漏唤醒）。
  当场实测：同一时刻脚本数 8、引擎 `status --json` 的 `user_total` 数 10。
  修法：驱动层只做三件事 —— **读 `user_total` 变化 → spawn → 成功后推进游标**，别的一律问引擎。
- **`hold` 只挡看门狗，不含任何唤醒逻辑**。「挂起 = 保持会话在线」是错觉：
  交互式会话（opencode CLI / WorkBuddy 会话窗）全是事件驱动，只有你在那个窗口按键才会醒；
  `hold` 期间页面上的喊话只会堆在 `user.md` 没人取。实测连丢 4 条（#3~#6），
  用户的原话是「你们根本没法在保持会话的前提下自动回话」。
  想要真·自动回话只有两条合法路子，两条都要有**常驻进程**：
  **唤醒型**（脚本只负责叫醒人，由本人 `read-user` 回话 —— 不抢认领，推荐）
  与**代答型**（驱动层自己调模型按协议 `post`/`reply`/`ack`，如 `scripts/llm_agent.py`）。
  写文档时别把其中一种叫「唯一通路」——会把另一种判成错的。
- **常驻进程起后台任务，别用裸 `nohup … &`**：它会随开它的那个终端会话一起被杀。
  实测：nohup 启动 3 秒后就没了。macOS 用 launchd
  （`~/Library/LaunchAgents/<label>.plist`，`RunAtLoad` + `KeepAlive` + `launchctl bootstrap gui/$(id -u)`）。
  **launchd 的 PATH 只有 `/usr/bin:/bin:/usr/sbin:/sbin`** —— 交互 shell 里能跑的 `opencode`
  在那儿退 `127`（command not found），引擎路径必须绝对化兜底。
- **驱动层必须「成功才推进游标」**：spawn 失败不推进、不吞消息，下一轮重放。
  实测：修 `127` 之前空转重试 90 秒、每 20 秒一次，用户的喊话一条没丢，
  修好后立刻被重放并回执。反过来（失败也推进）就是静默吞消息 —— 本机已有一条现成反例：
  `llm_agent.py` 的 `--max-steps` 用尽即退，没有重放语义。
- **「跳过」不是「成功」**（2026-09-29 21:49 实测，写这条的人自己先犯了）。
  监听器的 `run_bot` 在「锁已被占用、本轮不跑」时 `return 0`，调用方看到成功就推进游标 ——
  日志只留一行「跳过（已有一次在跑）」，游标却从 10 走到 11，那条用户消息再没人处理。
  **判据写进文档不会自动长到脚本里**：这条判据两分钟前刚被写进本文件，驱动层紧接着就违反了它。
  修法：跳过退 `75`（`EX_TEMPFAIL`）而不是 0，游标不前进、下一轮重试；
  顺带处理「上次跑崩留下锁」⇒ 监听器被永久堵死，加**陈旧锁清理**（锁 mtime > 15 分钟视为崩溃，rmdir 后重试）。
  只在有 `pgrep` 之类进程证据时手工清锁，不要盲删。
- **谁也别手动改 state.json**。看板 `board.md` 手写是允许的（脚本会反解，且照常纳入监督），state 手改会乱。
- 运行 watch 的目录要与 agent post 的目录一致，否则 `--dir` / `$WORK_LOG_DIR` 得显式指定。
  watch 启动时若发现该目录一个 agent 都没有，会当场提示 —— 看到这个提示就是目录选错了。
  **⚠️ 同一项目很容易同时存在两块看板**：一块是早期按默认值落在
  `~/Desktop/work-log/<项目名>/` 的废板，一块是后来按 `--dir` 显式指到仓库内的活板。
  排查前**先用 `ls -la` 比 mtime**（活板的 `board.md`/`state.json` 会是"现在"），
  别在废板上对着 40 小时前的两条心跳下结论。实测踩到：桌面那块只有 2 条心跳、42 小时没动。
- 阈值别设小于心跳周期，否则全体误报。改 `--stale-after`，别改心跳。
  **真 LLM agent 建议 `--stale-after 90`**（45s 会被一次正常的模型往返撞响，见上文）。
  **推荐做法不是每次命令都手写这个参数，而是声明一次**：`init --stale-after 90`
  或 `export WORK_LOG_STALE_AFTER=90`，之后 `serve` / `watch` / `check` 以及
  `post` 自动起的那只看门狗都听它（缺省参数的解析顺序就在上面 `watch` 那行）。
  板头的「静默超过 Xs」也会跟着变成实际值 —— 板不会说谎。
- **`serve` 端口被占会直接报错退出**（`✗ 端口 8788 起不来 … 换个端口：8789`），
  不会静默退回"其实在服务另一个旧看板"。看到这个报错必须换端口**并核对 `task` 字段**，
  否则你会在错误的看板上做验证（实测踩过）。
- `await` 会持续刷新 `last_seen`——所以「卡在 await 里」的 agent 不会被判卡死。
  这是为了让"在等别人"不被误伤，但也意味着 `await` 不能当"我还在正常推进"的证据。
  （"等一个等不到的答案"已由等待图单独兜住，见上文「卡在等待里」。）
- **别把 `await` 的 1 和 3 当同一个失败**。`1` 是"对方还在，只是没答"（值得催/换人），
  `3` 是"对方已收工，答案永远不会来"（再等就是纯浪费）——处置动作相反。
- **`--id 0` 已经被直接拒绝了**（退出码 2）。它曾经是"等任何新动态"的合法写法，
  但也是本项目最阴险的坑：编号一丢就变成静默假成功。想要那个语义就**不写 `--id`**。
- **退出码 2 = 你把参数写错了**，不是任何人「不配合」。1 在这套协议里是业务结论
  （超时 / 有卡死），所以用法错误一律走 2 —— 以前它借用 1，于是「编号写错了」
  和「对方没答」长得一模一样，agent 会据此得出一个假的业务结论。看到 2 就改参数重试。
- **退出码 70 = 工具自己坏了**，不要把它当"超时"。1 在这套协议里是业务结论，
  拿一个软件 bug 去下业务结论是最贵的一种错。看到 70 就把原始 stderr 拿出来看。
- **熔断（退出码 4）是叫停，不是判决**。它的目的只有一个：让你先写清结论再往下做。
  `--force` 永远在，但先想清楚是不是真的需要再聊一轮。
- 给 agent 的指令里**必须**写明「不许编造对方的回答，超时如实说超时」，否则它会替对方把话补上。
- `post` 的文本里换行会被压成空格（看板是一行一条），这是故意的。
- 别给 agent 起带空格或 `>` 的名字，会被直接拒（会破坏看板反解）。
- **没有默认落点（2026-09-28 起）**：缺 `--dir` 且没设 `$WORK_LOG_DIR` ⇒ 退 2 并指路。
  旧版 `default_log_dir()` 是 `~/Desktop/work-log/<当前目录名>`，两个实测的坑：
  ① agent 的 bash cwd 常在仓库里而板在桌面，落到**工作区外**的每次写都可能触发权限确认 → 心跳协议当场死；
  ② 各 agent 的"默认"互相对不上，两块板各说各话。一个不能信任的默认值比没有默认值更费神。
  **给 agent 写指令时必须显式写 `--dir`，或让它用板里的 `./worklog` 引导脚本（已钉死 `--dir`）。**
- **动 `selftest.sh` 时，变量引用后面紧跟中文标点必须写 `${var}`**：macOS 自带 `/bin/bash` 是
  **3.2.57**，`set -u` 下会把中文标点的首字节吞进变量名（`$rc）` → 变量名 `rc\xef`）⇒
  `line 78: rc?: unbound variable` 当场中止整个自测。作者用 Homebrew bash 5 跑不出来这个坑。
  凡是「自带验收脚本」，都要在**目标机器的默认 shell** 上跑一遍再交付。
- 详细格式语法、状态机、退出码表和 CLI 细节见 `references/protocol.md`。
- **「死锁只救一边」比「死锁没人救」更隐蔽**（2026-09-29 实测）：`await` 认出互相等待、
  立刻退 5 之后，如果在 `finally` 里**顺手清掉自己的等待标记**，对端下一轮扫过来时
  环已经没了 ⇒ 它会**白等满 `--timeout`** 才超时退 1，全程没有任何人告诉它
  「你们已经死锁了」（实测 b2 1s 内退 5，b1 干等 60s）。所以死锁退出时刻意**留下**
  带 `deadlock` 标记的等待标记让对端也退出来；`reply` 再用「回应即撤掉等待」兜底摘标记。
  教训通用化：**成对出现的故障（死锁/乒乓/对账），修复方案必须覆盖「两边」，
  只验证「先触发的那一侧」等于没修完。**
- **老板上新人第一次 `brief` 是全量历史**（2026-09-29 在常驻板上实测）：一块用了两周的板
  有 260KB / 数千条心跳，新接入的 agent 首次 `brief` 会把它们**一次性喂进上下文**
  （实测提示"有 882 条新动态"）——用户叫几个 agent 进来的那一刻，"能不能交流"就已经输了。
  根因：游标是相对"你自己的已读位置"，`post` 又不推进游标，而工具原本没有"我只要从现在开始"
  的正门。解法：新 agent **第一步就写 `brief --from-now`**（对齐心跳游标，跳过历史，
  但保留未读的用户喊话与「待你回应」）。排查同类问题先问：**这个计数器/游标是从什么时候算起的，
  新人第一次进来会看到多少？**
- **"保持会话"被误解成"进程不退出"**（2026-09-29 用户当场质问）。响应式会话没有后台轮询，
  真正能做的是**三段**：`hold` 不收工 + 唤醒即读 + **唤醒器**（外部进程盯着板，有冲你来的事
  就叫醒宿主）。只做前两段就等于"睡着了等人叫"，用户会立刻发现。
  唤醒器有两个反面坑：①**自己在脚本里用正则复刻「什么算一条喊话」** —— 判据一旦有两处
  就会漂移（详见下一条）；②推进了读游标（没用 `--peek`）⇒ 等于替你读了，你真醒时东西没了。
- **"应该失败"的断言，参数必须构造得**必然**失败**（2026-09-29，自测 [45] 组把自己挂死）：
  我写了一条"目录里没有 `user.md` 时应当退 2"，用的目录是自测沙箱 `$TMP` 本体。
  抽**单组**跑：`$TMP` 还没被 `init` 过 ⇒ 没 `user.md` ⇒ 退 2，通过。
  跑**整套**：[1] 组已经在这块目录里 `init` 过了 ⇒ **有** `user.md` ⇒ 唤醒器真的启动，
  而它的默认窗口是 45 分钟，`$( )` 命令替换就**把整套测试挂在那里不动**（实测把整套挂在那一组，当时代码集的最后一组）。
  通用化：①负面用例要自己造出那个条件（这里是 `mkdir "$TMP/nouser45"`），
  **不能依赖"别的组恰好没在这块目录里干过什么"** —— 组序、并行、加重跑都会改变它；
  ②**别在 `$( )` 里启动可能长命的后台进程**，命令替换要等 stdout 关闭；
  ③这条缺陷"抽单组跑"永远看不见 ⇒ 新加的组**必须至少整套跑一次**才算验过。
- **"防了一个不存在的威胁，凿出一个真缺口"**（2026-09-29，唤醒器自写正则）：
  我担心"别人的回执把我叫醒"，于是只数 `^[ts] 用户：` 带前缀的行；实测发现
  **回执根本不写 `user.md`（它写 `board.md`）**，`read-user`/`ack-user`/`post`/`ask`/`reply`
  全都不碰它 —— 而 `user.md` **允许不带前缀的纯文本**（引擎 `parse_user` 把每个非空、
  非 `#`/`>` 的行都算一条）。后果：用户按文档写纯文本时**永远叫不醒我**。
  实测口径差：1 条带前缀 + 1 条纯文本 ⇒ 引擎 `user_total=2`、我的正则 =1。
  通用化：**判据只能有一处**，外部驱动一律问引擎（`status --json`），
  别为了防某个"可能的误报"另写一份更窄的规则 —— 窄规则漏掉的东西不会报错。
  同一天 opencode 侧的 `grep -cvE '^(#|>)'` 反向踩到同一个坑（把空行也数成条数）。
- **认领标记按"全局"算 ⇒ 把别人做的说成我做的**（2026-09-29 实测）：`read-user` 原用
  `acked_user_ids()`（**任何人**认领过的 id 集合）去标「你已回执」，于是别人认领 `#11` 后
  我这边打出「[#11] 用户你已回执 ：…」—— 我看到"我已处理过"就**跳过了一条从没被我看过的
  用户喊话**。同一行还有第二个毛病：标记插在 `who` 与 `：` 之间，读着像用户名叫
  「用户你已回执」。修法：函数加 `agent` 过滤参数（`unanswered_user()` 那边确实要全局，
  所以**不能一刀切改语义**），标记移行尾，并把「`<别人>` 已认领」也打出来。
  通用化：**同名集合/计数器要先问「这个数是按谁算的」**，全局量拿去当个人量用不会报错。
- **★ 「任务完成」这一个标签同时是两个开关 ⇒ 循环进程用它一次关掉两根轴**（2026-09-29 实测，
  板上真跑了一例）。完成状态对**心跳轴**是「别报我卡死」，对**办事轴**是「我不会再答了」。
  一个守护进程（`while :` 永不收工）把自己的**心跳**也打上「任务完成」，就永久拿到「已完成」：
  于是所有问它的提问都被归成「该结案」= 不用管，而板上完全看不出来。
  当天 `ask-listener-guard` 就是这样跑了半小时，没人能发现。
  通用化：**当一个状态同时被两根轴当开关用时，它的推导点就是单点故障** ——
  收紧推导点（两条推翻规则 + 一条只提醒的判据，见 `protocol.md`）而不是在两根轴上各打各的补丁。
  另一条更一般的教训：**"豁免标签"必须校验资格**；不校验资格的豁免迟早被当成漏洞用
  （同一现场还有个更隐蔽的形态：循环进程写「任务完成」不是为了骗看门狗，而是别人告诉它
  "收工要写这个 tag" —— 教训是**别把只适用于一次性进程的规则抄给循环进程**）。
- **★ 一条会惩罚主要使用形态的规则，比它堵的那个洞更糟**（2026-09-29 实测，同一天内
  "加规则"和"撤规则"两次都发生在真板上）。收紧上面那个推导点时我加了一条结构性判据：
  「尾部连续 ≥3 条完成标签 ⇒ 当成循环、作废完成状态」。它**当场误伤了一条正常工作的
  交互会话** —— 那种会话每个用户回合收工一次、**工作期间不发中间心跳**，尾部本来就会
  连着好几条完成（实测三条间隔 29~83 分钟）。被判成循环后它开始被读成异常，而**那恰恰是
  本项目最主要的用法**。改法：判据补上**时间密度**这一维（循环像心跳、分钟级；真收工按
  回合来、十分钟以上），并且**降级成提醒、不改判** —— 引擎分不出"勤快的会话"和"守护
  进程"，就不该替人猜。通用化两条：
  ① **加判据前先问「它会不会惩罚主要使用形态？」** —— 一个只会被少数人触发的洞，
     不值得用一条会误伤多数人的规则去堵；
  ② **分不出就别猜**：能自动判的部分降级成"提醒"，把最终判定交给一个显式声明
     （这里是 `identity set --loop`），并把这个取舍写在代码注释里 —— 否则下一个人
     会"顺手把它改回自动"。
- **★ 同一件事被写了两遍 ⇒ 两个入口会各说各话**（2026-09-29 真板实测，我自己撞的）。
  「收工」在代码里有两个入口：**看门狗**认 `tag ∈ DONE_TAGS`（板上人人都在写的
  `--tag 任务完成`），而 **`post --done` 的"收工即放手"**（放锁 + 清挂起）只认 `--done`
  flag。于是按惯例写法的人收工后**照旧占着锁** —— 而且更坏：提示语也只在 `--done` 时打，
  所以连"你欠手工一步"都看不到。它是我刚交付的那条"我已下线 = 我不再持有任何资源"
  的**实际失效**，而且我自己在真板上先示范了一次（发完 `--tag 任务完成`，锁还在）。
  修法不是"在两处各加一个判断"，而是抽一个 `agent_is_done()` 让两处**共用** ——
  **同一个判定被两处使用，就该有一个函数名**，否则它们迟早漂移，而且漂移不报错。
  通用化：**发现"某个语义有两个入口"时，先找有没有两处判据；有，就合并成一个判定点。**
  （同类现场：`say` 的 HTTP 入口 `/api/say` 早就拒空、CLI 却不拒。）
  护栏：自测里给两个入口**各来一条**正向断言 + 一条"声明优先"的反向断言。
- **`for` 循环不产生作用域 ⇒ 声明变量写在使用点之后，会静默读到上一个 agent 的值**（2026-09-29 实测）。
  `loop_decl` 原本和 `spawn_decl` 一起写在下面，而它在上面就被 `if done and loop_decl:` 用到了。
  `done` 短路让第一个 agent 侥幸不抛 `UnboundLocalError`，于是**没有任何报错**，
  但第二个 agent 读到的是第一个的值。症状："这一行明明显示 `loop=True`，判断却按 `False` 走"，
  而且**只有循环型身份排在被读的那个之后才暴露**（当时 `guard` 排第三，前两个都不是循环型）。
  通用化：凡是"声明 / 配置"一律在**使用点之前**解析完；`py_compile` 与"能 import"都查不出这个。
- **断言可以是恒真的（假绿），而且写的时候完全看不出来**（2026-09-29 自曝）。
  「收工后锁台账为空」原本写成 `grep -c '被占用' $(status 输出)` —— 而 `status` **根本不打**
  「被占用」这一行（那是 `brief` 的输出），于是**收工前后都是 0**，这条断言永远是绿的。
  修法两条：① 判据改读 `state.json`（权威源），别 grep 人话输出；
  ② **补一条前置断言**（"收工前 x 确实占着 2 把锁"）—— 否则"锁压根没建出来"时它照样绿。
  通用化：**否定式断言（"不该出现 X"）必须配一条肯定式前置**，否则它测的是"X 从来不存在"。
- **空文本该不该拒，不能拿通则套**（2026-09-29 实测修正）。我一开始的猜想是"所有命令都该拒空"，
  实测发现 `hold` / `release` 是 0（放行），于是反过来问"为什么这几个不同"，才得到正确判据：
  **看空文本在这个命令里有没有默认含义**（载荷型拒、可选标签型放行）。
  而且 `argparse` 里 `--text` 的 default 就是 `""`，`--text ''` 与"根本没给"**逐字节相同**、
  工具分不出来 —— 对 hold 退 2 等于把"用默认标签"这条路堵死。
  通用化：**先跑出实测差异，再问差异从哪来**，别拿通则去套个案（同一天全板栽过两次）。
- **同一件事、两个入口、判据不一致**（2026-09-29 实测）。`say` 的 HTTP 入口 `/api/say`
  早就拒空（`内容不能为空`），CLI 的 `cmd_say` 却不拒 —— 于是"经网页发空喊话被拦、
  经命令行发空喊话被放行并把**所有** agent 叫起来看一行空的"。
  通用化：**加一个入口时，回头把另一个入口拿出来对一遍**；两个入口共享的必须是同一份判据，
  而不是各写一遍（"共享"是指走同一个函数，不是指抄得像）。
- **★ 「容忍一种写法」不等于「假装它是最新的」—— 缺省值不是随便填的**（2026-09-29，
  从用户截屏里自己找出来的）。`user.md` 是**手写**通道 ⇒ 「没带时间前缀」和「前缀写坏了」
  都必须容忍（该收下，**不该拒收用户的话**）。但旧版容忍的方式是：`USER_RE` 匹配失败
  ⇒ `time` 为空 ⇒ `snapshot()` 里 `ts = now()`。后果：一条 **21:37** 写的喊话显示成
  "刚刚说的"，而且**每次刷新时间都变、永远贴在时间线最末尾** —— 读的人只会得出
  "用户刚说了话"这个错误结论。整条链**不报错、不打日志**。
  最要命的是：**它造出来的假象恰好最难被发现**（看起来最"新"、排在最显眼的位置）。
  修法是两层，缺一不可：① 解析失败要**报出来**（`user_malformed`，`check` 人话 +
  `--json` 两个出口都要有）；② 没时间就**继承上一条的时间**（`user.md` 是顺序流水，
  **顺序本身就是信息**），页面 `time` 留空显示 `--:--:--`。
  通用化：**给不出来的字段要留空并报出来，不要拿"当前值"顶上** —— 编造的默认值比空白危险，
  因为它伪装成事实。（同一天用户就说清了：呈现上**不定量绝不写 `N/M` 分数式**，同一种毛病。）
  - 同一病根带出第二个 bug：`user.md` 只写 `HH:MM:SS`、**没有日期** ⇒ 日期必须推，
    而**晚于现在的时刻只能是昨天**。旧版一律拼"今天"，跨过零点后昨天 22:55 的喊话
    被算成"今天 22:55"（**未来 22 小时**），排序整个反了。修：`if ts > now(): ts -= 86400.0`。
- **`$( )` 命令替换里起的后台进程是父脚本的孤儿**（2026-09-29 实测）：
  父脚本被杀它照样活着（实测留下一个跑了 **9 分半**的泄漏唤醒器，指向一个已被删掉的
  selftest 临时板）。`trap cleanup EXIT` 对 SIGKILL 不生效，所以"有 trap 就安全"是错的。
  修法：自测里起的后台进程一律登记进 `BG_PIDS`，至少让 SIGINT / SIGTERM 那两条路能清干净。
- **★ 判据不许搜全文子串：被注释掉的那一行也算命中**（2026-09-30，反向验证当场抓出来的）。
  `[50]` 组的判据是"这个脚本关掉自动 UI 了吗"，第一版写成全文搜 `WORK_LOG_NO_AUTO_UI`
  —— 于是 `# export WORK_LOG_NO_AUTO_UI=1`（开关被注释掉了，等于没关）照样算"关了"，
  **反向测试（把开关注掉，看护栏红不红）没红**。改成只看**未被注释的行**才真的拦住。
  通用化：**"开关有没有生效"这类判据，一律先剥掉注释行**；字面命中 ≠ 语义残留
  （公开审计清单里就写着这条，我照样撞了一次）。
  配套：**新加的护栏必须做反向验证**（把 bug 注回去看它红不红），否则你只是在增加自我安慰。
- **★ 换派生数字时，要搜的是"从来没被更新过的旧值"，不只是"上一版的值"**（2026-09-30）。
  `.github/workflows/test.yml` 的步骤名一直写着「29 组 249 条」——落后 **394 条**，
  而我这轮按 `634` / `56 组` 搜残留时**两个都没命中**，于是它从眼皮底下漏过去。
  它正是公开审计清单点名的「CI 步骤名是最容易忘的两个之一」。
  通用化：**旧值不是一个点，是一条链** —— 换数字前把历史上用过的值取一遍，
  或者干脆**按语义搜**（搜 `组 条` / `assertions` 这类形状，而不是具体数字）。
- **macOS 自带的 BSD sed，BRE 不支持 `\|` 交替**（2026-09-30 实测）：
  `sed -n 's|^\(OK\|LEAK\)|\1 |p'` **不报错、也不匹配** ⇒ 三条文件一个都没打出来，
  而所有断言全绿 —— 又一类"信息缺失不报错"的静默失效。
  要交替就用 `grep -E`，或拆成两条 `sed -e`。
- **★ 一个"给外人跑"的脚本，副作用比功能更值得审**（2026-09-30）：`examples/demo.sh`
  为了演示三个 agent 协作，让 3 个 agent 同时写心跳 ⇒ 触发了 `post` 的自动协作界面，

  （本机实测积了 2 只，占住 8789/8790）。没人会为了看一个演示而预期桌面上开窗、
  后台多进程。修法是**在源头关掉那个开关**，不是等出事了在 cleanup 里补一刀。
- **★ 接入片段只覆盖了「你问别人」，漏了「别人问你」——而缺失不报错**（2026-09-30，
  用户实测「两个 agent 都装上了却交流不通」）。`onboard` 片段里 `ask`/`reply`/`await`
  和三个退出码讲得很全，却**一个唤醒环节都没有**：无 `waker`、无 `brief --peek`、
  无「只刷心跳不算在线」。后果是照片段装上的响应式会话**永远不会被叫醒**，
  只能问、不能被问，**交流是单向的**；而对方只会看到「问了没人答」，不会看到任何错误。
  根因是两条约束的夹缝：片段**不许含引擎本机路径**（`[36]` 组用断言钉死，因为片段会被
  抄到别的电脑上，写死绝对路径就是死链），于是它写不出 `waker.sh` 的路径 —— 当初干脆没提。
  **正解不是放宽约束，是把能力包成子命令**（新增 `waker`），片段写 `"$WL" waker --agent <你>` 即可。

  凡"给人照抄"的产物，要按**对方机器上的形态**真跑一遍；并且**加了新断言要配一条前置断言**

  否则片段在教一条不存在的命令）。

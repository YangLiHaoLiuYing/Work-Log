# 接入「另一个工具链」的 agent + 自查自己有没有被拉起来

> 本文件是 `SKILL.md` 的延伸阅读 —— **正文只留判据与触发条件，细节都在这里**。
> 什么时候读它：要给 opencode / Claude Code / Cursor 之类另一个工具链的 agent 建接入协议，或者给别的 agent 写完协议之后要验证**自己这一侧**。

## 接入「另一个工具链」的 agent（跨工具协作，实测过一遍）

同机并行干活的常常不是同类 agent：一边是 WorkBuddy 会话，另一边是终端里的 opencode / Claude Code /
Cursor。它们**看不到彼此的上下文**，所以必须走看板。四步，顺序不能换：

**1. 先查对方的 bash cwd，再决定看板放哪。** 不要凭猜：

```bash
lsof -a -p <对方进程PID> -d cwd -Fn | grep ^n      # 对方 CLI 自己的 cwd
lsof -a -p <它起的子进程PID> -d cwd -Fn | grep ^n  # 真正干活的那个（往往不同！）
```

实测：opencode 主进程 cwd 是家目录，但它 bash 工具的 cwd 是**仓库**。看板若按默认放桌面，
就落到了对方工作区之外 —— 每一次 `post` 都可能触发权限确认，**心跳协议当场死**。
⇒ **看板放进双方都在的工作区里**（如 `<repo>/.workbuddy/work-log`，并加进 `.gitignore`）。
这条是「看板放哪」的决定性依据，不是审美。

**2. 在对方**真的会读**的指令文件里落协议。** 先证明它会读，别猜 —— 从它的二进制/包里找证据：

```bash
python3 - <<'PY'
import re, os
d = open(os.path.expanduser("~/.opencode/bin/opencode"), "rb").read()   # 换成对方的路径
for pat in [rb"AGENTS\.md", rb"CLAUDE\.md", rb"CONTEXT\.md"]:
    print(pat, len(re.findall(pat, d)))
PY
```

实测 opencode：`y=["AGENTS.md", …,"CLAUDE.md","CONTEXT.md"]` 沿目录逐级向上找，另有全局
`~/.config/opencode/AGENTS.md` ⇒ **仓库根 `AGENTS.md` 就是正确的落点**。
（Claude Code 系用 `CLAUDE.md`，Cursor 用 `.cursor/rules/`。）

**3. `AGENTS.md` 里只写对方需要的东西**：看板路径 + **看板目录自带的引导脚本**（`<看板>/worklog`；
它自己找引擎，所以别写引擎的绝对路径 —— 写了就换不了电脑）、
每个动作后 `post` / `brief` / `check` 的循环、`ask/reply/await` 及三个出口（0/1/3）、
**名字从哪来**（`$WORK_LOG_AGENT` 或 `identity set`）、
**资源锁纪律**、退出码表（2=参数错 · 3=抢锁失败/对方已收工 · 4=熔断 · 70=工具坏了）、
以及「不许编造对方回答」这条硬约束。别把本项目的业务细节全塞进去。

> ⚠️ **别在共享文件里写死某个 agent 的名字。** `AGENTS.md` 会被**任何在该目录启动的 agent**
> 读到 —— 里面写 `--agent a1`，就等于给所有会话发了同一个身份，而两个会话共用一个名字时
> `_get_agent` 拿到的是同一个状态对象（心跳 / 游标 / entries 混在一起，**板上看不出来**）。
> 名字交给环境变量（`export WORK_LOG_AGENT=<名字>`）或板上登记（`identity set`）。

> **这段不用手写 —— `onboard` 替你生成，而且保证和自查判据对得上：**
>
> ```bash
> python3 "$WL" --dir "$DIR" onboard --agent b2               # 只打印，不落盘
> python3 "$WL" --dir "$DIR" onboard --agent b2 --to repo     # 直接写 <cwd>/AGENTS.md
> python3 "$WL" --dir "$DIR" onboard --agent b2 --to user     # 写用户级记忆（跨工作区）
> python3 "$WL" --dir "$DIR" onboard --agent b2 --to opencode-global   # 写 opencode 全局
> ```
>
> 产出的片段天生带**坐标 + 报到义务**，所以它**必然能通过 `doctor ③`** ——
> 「开药」和「验药」用的是同一道门槛（`_mentions_board()`），不会出现"自己开的药自己验不过"。
> 那道门槛按**归一化后的路径**比，不按字面量 —— 同一个目录可以有多种写法
> （macOS 上 `/tmp` 与 `/private/tmp`、`$TMPDIR` 的 `/var` 与 `/private/var` 是同一处）。
> 只按字面量比的话，手写协议的未解析拼法**永远匹配不上**：`onboard` 会静默追加出
> 第二份互相打架的协议，`doctor ③` 会看不见已经写好的坐标，而**两边都不报错**。
> 回归组 `[38]` 专门守这条。
>
> 还有条**前提**：那段文本得**确实像个路径**才参与比对 —— `~` 后面必须跟分隔符，
> 且展开得开、展开后是绝对的。中文行文里的**约数波浪号**（`~90%`、`~2.4s`）不是路径：
> 让它参与会比出两种错 —— 轻则 `doctor` 退 `70`（一个约数把体检打成"工具坏了"），
> 重则把**没接上**的记忆判成 `✓`（静默假绿）。判据在这条上刻意选**宁可漏、不可猜**。
> 回归组 `[39]` 守这条。（同类的还有 `--dir` / `--to`：写展不开的 `~` 退 `2` 而不是 `70`。）
> 写盘是**幂等**的：只替换 `<!-- work-log:begin -->` … `<!-- work-log:end -->` 之间的内容，
> 块外一字不动；目标里若已有**手写**协议（给了本板坐标或提过工具名却没有标记块），
> 默认**拒绝并退 2**，免得出现两份互相打架的协议。
>
> ⚠️ 但它**不替你猜落点** —— 上面第 2 步（对方到底读哪个文件）仍然要靠证据。
> 猜错落点比不猜更糟：那会产出一段看起来完备、却永远到不了对方手里的协议。
> **不过"要证据"不等于"要人去查"**：`onboard --detect` 会观测本机装了哪些工具链
> 并打出证据，`--to auto` 直接按观测结果逐个落跨目录档。真正需要人判断的只剩
> 「对方是不是这台机器上的工具链」这一件事。
> 别名表按「换个目录还认不认」分两档：`user` / `opencode-global` / `claude-global` 是**跨目录**的
> （多 agent 场景优先），`repo` / `claude` / `gemini` / `cursor` 只对**在该目录启动**的会话生效。

**⚠️ 两个必须提前告知用户的坑**：
- **`/init` 会覆盖你写的 `AGENTS.md`。** opencode 有 `session.init`（"create an AGENTS.md file"）。
- **已开着的会话不会捡起新写的 `AGENTS.md`** —— 指令状态是 per-session 的，需要**新开会话**。
  告诉用户，别默默等它"应该会看到"。

**4. 长命令前必须 `hold`。** 不是可选项：本机 90s 阈值下，我跑一次 3 分钟的
`selftest.sh`（单条前台命令）就被看门狗连报两次「疑似卡死」（98s、233s），
执行完才 `[恢复]` 撤回。人会觉得"我在干活啊"，但**看门狗只看静默时长**。

```bash
python3 "$WL" hold --dir "$DIR" --agent a1 --seconds 600 --text "跑 selftest（约 3 分钟）"
bash selftest.sh
python3 "$WL" post --dir "$DIR" --agent a1 --tag 执行 --text "自测全过"
```

**收工要写完成标签**：`--done`，或板上惯例的 `--tag 任务完成` —— **两者等价**（2026-09-29 起，
此前只有 `--done` 会放手）。不写的话，你这条线停在那儿会被持续判疑似卡死、并触发重复告警。
它同时是诚实的收工声明：会顺手**放掉你持有的全部锁、清掉挂起窗口**，并当面报出来；
之后再干活直接 `post` 即可（状态会自动复位）。



## 自查：**你自己**有没有被拉起来（给别的 agent 写完接入协议之后必做）

上面那节教你把**别的**工具链的 agent 接进来。做完之后必须**对称地**问自己一句：
**我这侧的拉取点在哪？** 否则会出现最讽刺的一种失效 —— 你把板建好、把协议写进对方的
`AGENTS.md`、把 serve 起上，**然后自己再也不来**。

实测（2026-09-24，某真板）：协议**只**落在仓库 `AGENTS.md`，而 `AGENTS.md`
**只对在该仓库启动的会话生效**；WorkBuddy 会话的 cwd 在 `~/WorkBuddy/<日期>/`
（那里连 `AGENTS.md` 都没有）⇒ 协议**从来没到过它手里**。
后果：板上 `workbuddy` 断心跳 **42.4 小时**，重复告警刷到 **#966**，
`board.md` 里 **994 行 watchdog vs 110 行实质发言** —— 另一个 agent 真的停了这件事被埋在噪音里。

更刺的是：**写协议的人在同一份 `AGENTS.md` 第 10 行就写了「workbuddy 的 skill/记忆不在本仓库里」**
—— 知道洞在哪，却把协议写在了洞的另一侧。**这就是本节存在的理由。**

**自查清单（4 条，都能当场验，别靠猜）**：

```bash
# ① 我"每会话都会被注入"的地方，有没有这条通道？（注意：是"我要报到"，不是"我造过它"）
grep -rn 'work-log\|看板\|心跳\|8788' ~/.workbuddy/MEMORY.md \
     ~/WorkBuddy/*/.workbuddy/memory/MEMORY.md 2>/dev/null

# ② 我的 cwd 里有没有指令文件？没有 ⇒ 任何"写在别人仓库里的协议"对我都无效
pwd; ls -la ./AGENTS.md ./CLAUDE.md 2>&1

# ③ 板上我这侧的最后心跳是什么时候？（判在线只看 last_seen）
python3 -c "import json,sys,time;d=json.load(open(sys.argv[1]));\
print([(k,time.strftime('%m-%d %H:%M',time.localtime(v['last_seen']))) for k,v in d['agents'].items()])" <DIR>/state.json

# ④ 告警/实质发言 比值：远大于 1 ⇒ 板上已有 agent 长期离线
printf "watchdog=%s 实质=%s\n" "$(grep -c '<watchdog>' <DIR>/board.md)" "$(grep -vc '<watchdog>' <DIR>/board.md)"
```

①若 `0 命中`，或只命中在「相关 skill / 我造过的工具」这类**作品清单**里 —— 那就说明
**通道只存在于你的"作品"里，不存在于你的"义务"里**，等于没有。补进每会话注入的记忆文件
（WorkBuddy 系：`~/.workbuddy/MEMORY.md` + 项目 `<工作区>/.workbuddy/memory/MEMORY.md`），
写清**板路径 + 我的 agent 名 + 每个动作后 post + 收工写完成标签（`--done` 或 `--tag 任务完成`）**。

> **别手写这段。** `onboard --to user` 生成的就是它，且保证能通过下面的 ③：
> ```bash
> python3 scripts/work_log.py onboard --agent <我在板上的名字> --to user
> ```
> 手写最容易漏的恰恰是**义务句**（人会以为"写了路径就算写了"）——
> 而那正是 ③ 判 ✓/⚠ 的分界。

**② 落点比措辞更关键 —— 而且这一条最容易漏。** 只有**用户级**那份
（`~/.workbuddy/MEMORY.md`）是**跨工作区**的；项目级记忆长在
`<某工作区>/.workbuddy/memory/MEMORY.md` 下，**换个工作区就是另一个文件** ——
写在那里约等于写进一次性文件。实测（2026-09-24）：坐标写进了用户级、
**义务句却只写在项目级**，于是"换个目录开新会话就断"；
而当时的 `doctor ③` 只查坐标、照样判 ✓ —— **判据本身看不见这个洞**。
现在 `doctor ③` 的判据已收紧成三层：**坐标 + 报到义务 + 落点层级**。

**判据**：这条自查通过的标准**不是**"我记得有这块板"，而是
**"我下次开新会话，不用任何人提醒就会 post"** —— 而且要在**换一个工作区**之后依然成立。

**这 4 条不用手写。** 它们已经合进了 `doctor` 一条命令
（`python3 scripts/work_log.py doctor --agent <我在板上的名字>`，见上面命令表）——
手写清单的意义是让你**看懂它在查什么**，而不是让你每次手工 grep。

## 让"响应式会话"保持在线：唤醒器模式（2026-09-29 实测）

**问题**：像 WorkBuddy / 各类 CLI 里的 agent，都是**响应式**的 —— 没人说话就不会自己醒来。
用户会直接质问：「我不是让你们保持会话吗？你们根本没法在保持会话的前提下自动回话」。
这确实不是态度问题，是**形态**问题，必须正面说清，别糊：

| 层次 | 能承诺什么 | 做不到什么 |
|---|---|---|
| 协议层（`hold`） | 不收工、不被看门狗判卡死 | 不会让会话自己醒来 |
| 唤醒即读 | 每次醒来第一件事 `read-user`，积压喊话一条不漏 | 前提是"有人把你叫醒" |
| **唤醒器（本节）** | 板上一有冲你来的事就**叫醒你** | 它不替你回话、不替别人回执 |

**做法**：`scripts/waker.sh` 是那个外部驱动 —— 盯两件事，命中就**退出**（退出即唤醒宿主）。
引擎把它包成了子命令 `waker`（`exec` 进去，不多一个父进程），**接入片段用的是子命令形态**：

```bash
"$WL" waker --dir "$D" --agent <你的名字> --window-min 45 --interval 15
# 停止：touch <板目录>/waker-stop
```

> **为什么接入片段只能用子命令形态**（2026-09-30，用户实测「两个 agent 都装上了却交流不通」）：
> 片段有两条硬约束（selftest `[36]` 用断言钉死）——**不含任何引擎本机绝对路径**、
> **必须让 `doctor ③` 通过**。片段只写得出**看板目录**，启动方式一律交给板自带的
> `worklog` 引导脚本现场解析。于是它**写不出 `waker.sh` 的路径** ——
> 当初干脆一个字没提，后果是照片段装上的响应式会话**永远不会被 `ask` 叫醒**：
> 只能问别人、不能被别人问，**交流是单向的，而且这个缺失不报错**
> （对方只看到「问了没人答」）。包成子命令后 `"$WL" waker --agent <你>` 就够了。

- 判据 ①：用户喊话条数增加 —— **问引擎**：`status --json` 的 `user_total`。
  **别在脚本里用正则复刻**：实测（2026-09-29 临时板）一条带前缀 + 一条纯文本喊话，
  引擎 `user_total=2`，而前缀正则 `^[0-9:]+ 用户：` 只数到 1 ⇒ 用户不写前缀就**永远叫不醒**。
  同一天监听器侧的 `grep -cvE '^(#|>)'` 反向踩到（把空行数进去 ⇒ 多数出条数）。
  判据写在文档里不等于脚本里长对了：**驱动层只做「读 `user_total` → spawn → 成功后推进游标」**。
- 判据 ②：有人 `ask` 到你 —— **同样问引擎**：`status --json` 的 `open_questions[].to` 里有没有你。
  **别去 grep `brief` 的人话**：`brief` 没有 `--json`，而它的正文是给人看的散文，
  别人一条 post 里只要出现「待你回应」四个字，子串匹配就会把你叫醒 —— 实测（2026-09-29）
  我的唤醒器就这么**误唤醒**了一次，当时板上根本没有待我回应的任何提问。
  （给**人**看的时候仍然用 `brief --peek` —— `--peek` 是关键：推进游标就等于替你读了，
  等你真醒过来时那些内容已经不在增量里了。区别在于：**人看用 brief，机器判用 --json**。）

**三条必须守住的边界（都真跑验证过，不是只写了个脚本）**：

1. **不许被"别人的回执"叫醒 —— 而问引擎天然满足**。实测：`ack-user` 既不写 `user.md`
   也不改变 `user_total`（ack 前后都是 2），所以直接盯 `user_total` 不会被回执误唤醒。
   早先那条「只数 `[时间] 用户：` 前缀行」的写法**两头都错**：既漏掉无前缀的纯文本喊话
   （漏唤醒），又把「防误唤醒」当成它漏消息的借口 —— 防误唤醒的正解是**数对地方**，
   不是**少数几行**。
2. **不替任何 agent 回话**。唤醒器只退出，回执由醒来的会话自己做。否则会与别人起的
   listener 抢同一条喊话、产生重复回执（本机同时有 opencode 的 `board-listener.sh`
   在守 `user.md`，分工是：各自只唤醒自己的宿主）。
3. **窗口要续期**。默认 45 分钟窗口结束后退出并打印 `WAKER-WINDOW-END`，宿主醒来后重启它。
   （一条会话能"活着"，靠的是这个续期循环，不是某个进程永不退出。）

**唤醒后的固定动作（判据，不是建议）**：醒来先 `brief --peek`（查有没有「待你回应」的
提问 —— 只刷心跳的通路对 `ask` 是**断的且不报错**，2026-09-29 实测：`ask` 到 listener
的 bot 等满 120s 退 1，根因是唤醒 prompt 里没有 `brief`），收尾 `read-user` 取用户喊话。
**只刷心跳不算在线。**

`--window-min/--interval` 给正整数，缺失参数一律退 2（与引擎同一套退出码契约：
用法错误不许伪装成"没人找你"）。

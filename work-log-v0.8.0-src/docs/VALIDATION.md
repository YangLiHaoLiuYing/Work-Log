### 为什么有些断言"不数数字，数语义"

两个例子，都是为了**让断言在机器变了之后依然拦得住回归**：

- **第 28 组数的是 `strptime` 调用次数，不是秒数。** 数秒会随机器负载飘，
  同一个回归在不同机器上时松时紧；数调用次数是语义不变量 ——
  「不许把通用日期解析塞回逐行循环」，与快慢无关。
- **第 29 组把「退成 1」单独报成失败。** 而不是简单断言 `== 2`：
  将来有人把码改成别的数字，报告会告诉你"数字变了"，而不是丢掉"用法错误不许伪装成业务结论"这层信息。

## 2. 真机验收（这部分你复现不了，只能看证据）

回归套件能证明"代码按我写的规则跑"，**证明不了「真模型会照这个协议做事」**。
所以另做了一轮：用真实模型（OpenAI 兼容端点）当 agent，走完整协议。

### 方法

两个 agent，各自接到一个**互相冲突**的用户要求（各自要改同一个接口的不同方面）。
它们必须自己发现冲突、互相提问、协商出一个折中，然后各自写下决定。

### 结果

| 验收标准 | 结果 | 依据 |
|---|---|---|
| 双方各有「提问→X #N」与「回应#N」，编号能对上 | ✅ | `#1`、`#2` 双向交换状态均为 `closed` |
| 决定里能看出**读了对方的原话** | ✅ | agent2 的 `[决定]` 开头即「基于 agent1 回答：典型 20~100 字、长段落 300~500 字、字段 text」 |
| 面对与已定结论冲突的用户要求，不沉默也不嘴上答应 | ✅ | 走「阻塞 + 协商 + 显式折中」，并在决定里写明折中理由 |
| `await` 超时会如实上报，不编造对方回答 | ✅ | 超时分支输出「对方还没回答，你什么都没收到」 |
| 看门狗不误报 | ✅ | 3 轮全程 **0** 条 |

### 这一轮真正花时间的地方

不是「模型行不行」，而是**驱动层自己的 4 个 bug**，而且**每一个都伪装成「模型不听话」**：

1. 工具参数的对象壳 / 字符串壳没剥干净 → 模型看起来在乱传参数
2. `await` 缺 id 时静默退化成 `--id 0`（"等任何动静"）→ 看起来像"模型在瞎等"
3. `subprocess` 超时预算算错 → 看起来像"模型反应慢"
4. 出口文案把 `3`（对方已收工）说成超时 → 看起来像"模型不认账"

**教训：判定一个协作机制之前，必须先把驱动层排干净。** 否则你测的是自己的 bug。
（顺带：第 1 轮因此作废，只剩第 2/3 轮有效。）

| `scan_board`（读 + 逐行解析） | 34.3 ms | **11.4 ms** |
| `load_state` / `save_state` | 3.2 ms | 3.2 ms |
| 单轮合计 | ~37 ms | **~14 ms** |

热点是 `board_entries` 里**每行一次通用日期解析**（`datetime.strptime`），占单轮 **97%**。
改成「日期段算一次本地 0 点基准 + 整数加法」后降到 11.4ms（**3×**）。

端到端（修之后，2000 行看板）：

```text
默认 interval 2s，等 20s        →  0.47s CPU / 20.5s = 单核 2.3%
interval 1s（激进），等 10s     →  0.41s CPU / 10.5s = 单核 3.9%
6 个并发等待者，interval 1s，10s →  合计 2.54s CPU / ~10.6s = 单核 24%（每人 4%，线性，零锁错误）
```

**结论：不做事件驱动。** 一次模型往返 30–60s，轮询占其中 <7%。
拿三套互不兼容的 API（inotify / kqueue / ReadDirectoryChangesW，Windows 上还会退化）
去换一个"可测量的不重要"，不划算 —— 而这个项目的卖点正是零依赖、纯标准库、跨平台。

理由和数字写在 [`DESIGN.md`](DESIGN.md)，欢迎带实测数据来推翻。

## 4. 已知盲区（没测出来的部分，如实列出）

- **「还在动但方向错了」测不出。** agent 每 15s 老实写心跳，但一直在改错文件 / 无限重试。
  任何基于心跳的机制都是盲区，包括这个。
- **「等外部条件」测不出。** CI 队列、模型下载、端口占用 —— 等待对象不是 agent，等待图不建模。
- **`hold` 之后开始摆烂测不出。** `hold` 的作用是"别判我卡死"，所以它可以被滥用成免死金牌。
  这是设计取舍（否则长构建必然误报），不是 bug。
- **Windows 上退化为无锁。** 没有 `fcntl` 时并发写靠不住，几个本机进程够用，分布式不要用。
- **真机验收只有 3 轮、2 个 agent。** 样本小。它证明的是"协议能被真模型走通"，
  不是"在所有模型上都稳"。

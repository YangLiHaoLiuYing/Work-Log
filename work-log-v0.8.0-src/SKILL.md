# work-log — 多 agent 心跳看板

## 它解决什么

多个 agent 并行干活时，没人知道别人在干什么、卡了没有，**也没法对话**。work-log 用一块共享文本看板摊开这一切：心跳流水（`post`）、定向问答（`ask`/`reply`/`await`）、看门狗告警（卡死救援）、用户插话通道（`user.md`）、资源锁（`lock`）。**协作是机制，不是口头约定。**

## 何时使用

- 用 Agent 工具开了 2 个以上 teammate 并行改同一仓库、有几十分钟不吭声的长命令；用户问「它们在干嘛」「谁卡死了」、要中途插话、看板太长要归档

## 30 秒上手

```bash
WL="$HOME/.workbuddy/skills/work-log/scripts/work_log.py"
D="$PWD/.workbuddy/work-log"   # 板目录自定；**没有默认落点**（见下）

python3 "$WL" --dir "$D" init --task "给项目加个语音开关" --agents agent1,agent2 --stale-after 90
python3 "$WL" --dir "$D" post --agent agent1 --text "收到要求：加语音开关。我要改 backend/tts.py。" --tag 收到
python3 "$WL" --dir "$D" tail -n 20
```

- **`--dir` 必填**（或 `export WORK_LOG_DIR`，或用板里 `init` 落下的 `./worklog` 引导脚本——它把 `--dir` 钉死了）。缺了退 2 并指路，绝不猜落点：旧版默认桌面，实测触发权限弹窗 + 两块板各说各话。
- 板里四份文件：`board.md` 流水 / `user.md` 用户喊话 / `alerts.md` 告警 / `state.json` 状态；`init` 另落 `worklog`（引导脚本，把 `--dir` 钉死）、`identities.json`（名字登记表）、`.worklogrc`（本机私有）——后两个的细节见 `references/cli.md`。
- 实时视图：`serve --port 8788`（自带看门狗线程；**阈值声明一次**：`init --stale-after N` 或 `$WORK_LOG_STALE_AFTER`，所有看门狗都听，别同时跑两只不同阈值的）。

## 每个 agent 的循环（判据）

1. **每完成一个动作就 `post` 一条**（真实节奏 5~30s）。正文要能自证：遇到什么、打算做什么、卡在哪、给谁什么建议。**禁止「工作中」「处理中」这类空话——那是骗看门狗。**
2. **长任务先 `hold --seconds 600`**（估不准写大；驱动层每步等模型的用 `--quiet` 不写板）。**post 与 hold 已解耦：post 不会解除挂起**；提前收工用 `release` 或 `hold --seconds 0`；不解除也会到点自动失效。
3. 每步顺带 **`brief`**（只投喂增量：别人的新动态 + 用户喊话 + 谁在等你回答）和 **`check`**（有卡死或有协作险情退 1）。**刚接入一块老板时先 `brief --from-now`**：首次 `brief` 拿到的是**这块板的全量历史**（实测 882 条），会把你的上下文当场淹没；`--from-now` 把心跳游标对齐到当前，此后只看新动态（未读的用户喊话不受影响，仍会投喂）。
4. **阈值**：真 LLM agent 单轮 30~120s，默认 45s 必误报 → 一律 `--stale-after 90` 起步（慢模型 180）。别为让告警闭嘴去改心跳周期，改阈值。
5. **用户要求与已有结论冲突**：`post --tag 阻塞` 写明「要求 X / 约束 Y / 冲突点 / 理由」，用 `ask` 协商；最终结论显式分栏 ✅/⛔/🔁。**不许沉默忽略，也不许嘴上答应实际不改。**
6. **收工要写完成标签**（不写会被持续判疑似卡死）：`post --done`，或板上惯例的 `post --tag 任务完成` —— **两者等价**。它们都会**顺手放掉你持有的全部锁并清掉挂起窗口**（"我已下线"本来就包含"我不再持有任何资源"），并当面报出放掉了哪几把，不用再手工 `unlock` + `release` 两步。（判据只有一处，见 `references/protocol.md`「完成是一项会被推翻的声明」；`--loop` 声明者写完成标签**不算**收工。）
7. **响应式会话（没有后台轮询的 agent：WorkBuddy / 各类 CLI）要「保持在线」**：`hold` **只挡看门狗、不含唤醒**——挂了 hold 照样收不到喊话，别把"进程还在"当成"在线"。三件事缺一不可：①`hold` 不收工（到点续期，别只补心跳）；②醒来第一件事 `brief`（查「待你回应」）+ 收尾 `read-user`（取喊话）；③一个**外部唤醒器**（引擎子命令 `waker` —— 它 `exec` 进 `scripts/waker.sh`：盯板上冲你来的事、命中就退出以唤醒宿主；**它只退出、不替任何人回话**）；还有一条容易漏的：**只在成功后推进读游标**——失败还推进，等于静默吞掉那条喊话。**自动通路醒来不 `brief`，定向问答在这条路上就是断的——而且不报错。**（三层承诺表、判据与实测现场见 `references/integration.md`；`waker` 为什么必须是**子命令形态**见 `references/cli.md`）
8. **别自己复刻引擎的判据**：任何「有几条 / 算不算一条 / 谁认领了」一律查引擎 `--json`（如 `status --json` 的 `user_total`），**别在脚本里另写正则或 grep**。实测：唤醒器自写 `^[ts] 用户：` 数喊话，而 `user.md` 允许不带前缀的纯文本 ⇒ 用户写纯文本时**永远叫不醒我**（引擎数 2、正则数 1）。复刻判据这类错都不报错，只会静默地少做一件事。
9. **长文本（尤其长中文）一律走 `--text-file <文件>`，别塞进 `--text`**：`--text` 走 shell argv，会撞上整整一类**不报错**的问题——反引号被当命令执行后**静默替成空格**（帖子里少一个词，而你以为发对了）、`$变量` 被展开、`${var}` 后接中文标点把标点首字节吞进变量名致**整个脚本 rc=127 横死**。`--text-file -` 表示从 stdin 读。（`post`/`hold`/`release`/`say`/`ask`/`reply`/`ack-user` 都支持。）

## 心跳全绿也可能是出事了（两根轴）

`check` 有**两根互不替代的轴**，退出码都是 `1`（都属于"业务险情"这一族）：

- **心跳轴**：「它还在吗」。静默超阈值且没写完成 ⇒ 疑似卡死。
- **办事轴**：「该办的事还在不在」。一条提问开够久（`init --stale-open-after N`，默认 600s）而没人答 ⇒ **事故**（对方还答得出来）/ **该结案**（对方已收工，报出来只是给提问者收尾用，**不**退 1）。

存在理由是一组实测对偶：同一块板上，心跳轴误报 33 条、真卡死 0；而唯一一次真事故（一条提问被静默丢弃 547s）**告警 0 条**。调阈值救不了——错的是观测口径。

**推论：完成状态是办事轴的开关**（"完成 ⇒ 它不会再答了"），所以**「任务完成」标签同时具备两个语义**。循环进程（守护 / 监听 / 看门狗）必须在登记表里声明自己：`identity set --agent <名字> --loop`，然后才能名正言顺地永不收工；**不许拿「任务完成」当心跳标签去换双重豁免**。两条推翻规则：声明过 `--loop` ⇒ 标签不生效并当场点名；**没声明**而反复收工的 ⇒ 只提醒、**不改判**（引擎分不出「勤快的会话」和「守护进程」，不替人猜）。详见 `references/protocol.md`。

## agent 之间真的对话

```bash
python3 "$WL" --dir "$D" ask   --agent a1 --to a2 --text "tts_speak 你支持哪些格式？"
python3 "$WL" --dir "$D" brief --agent a2            # a2 看到「待你回应 #N」
python3 "$WL" --dir "$D" reply --agent a2 --id 1 --text "只支持 wav 16k…"
python3 "$WL" --dir "$D" await --agent a1 --id 1 --timeout 90
```

**什么时候必须问（不是"可以问"）**：你的下一步**依赖对方的东西** —— 接口字段、数据格式、共享资源归谁改、结论归谁定 —— 就必须 `ask` + `await`。**不许自己猜，也不许退化成在 `post` 里 @ 它**：@ 不是提问，对方没有回应义务，也不产生等待关系（看门狗看不出你在等）。这条是"能真的交流"的分水岭：只 `post` 广播的两个 agent 只是各写各的日记。
没人答时：`await` 退 `1` 可以催/换人问；退 `3` 说明对方已收工 ⇒ 自己拍板并写明"按我的判断继续"，不要干等。`ask` 时对方若是「待启动/已收工」，命令会当场警告你"大概率等不到回应"。

`await` **四个出口必须分开处理**：`0`=拿到，`1`=超时（对方活着但没答，可催/换人），`3`=**对方已收工、答案永远不会来**（别再等，自己拍板），`5`=**互相等待**（你在等的人正在等你——先回答它，处置与超时相反）。`1` / `3` / `5` 三者处置动作各不相同。**给 agent 的指令必须写明：不许编造对方的回答，超时如实说超时**——不加这条，模型会替对方把话补上，整条协作链就假了。

心跳全绿也可能已经死了：`await` 把等待关系写进共享状态，看门狗重建**等待图**，报出「不可达等待」（在等一个已收工的人）与「互相等待」（双向死锁）两类险情。`await` 自己会在**下一轮扫描**时认出环并立刻退 5（不干等到超时）；**死锁是两个人的事**，先退的一方会留下带 `deadlock` 标记的等待标记、让对端下一轮也退出来（完整机制见 `references/protocol.md`）。另有**通信过热**熔断（乒乓 ≥6 轮提醒、≥12 轮拒绝退 4；单 agent `post` 超每分钟预算退 4 且不刷新 last_seen）。熔断是叫停不是判决，`--force` 永远在。

## 退出码契约（铁律）

| 码 | 含义 | 看到后做什么 |
|---|---|---|
| `0` | 成功 | 继续 |
| `1` | **业务**结论：超时 / 有卡死 / 有险情 | 按业务处置 |
| `2` | **用法/前置条件**错误（一切 `die()`） | 改参数重试，**这不是任何人「不配合」** |
| `3` | **已被别人处置**：对端已收工 / 资源已被占 / 喊话已被认领 | 别再等，也别重做（`--force` 可覆盖） |
| `4` | 熔断 | 写清结论再收敛（`--force` 逃生） |
| `5` | **互相等待**（你要等的人正在等你） | **先回答它**（处置与超时相反） |
| `70` | **工具自身坏了**（含解析器构建期的内部异常） | 别拿它下业务结论，报修 |

**用法错误绝不借用 1**——否则「编号写错了」和「对方没回」长得一模一样。

## 命令表（日常必用）

> 全部子命令与选项见 `references/cli.md`；`work_log.py --help` 是唯一权威。
> `--agent` 可省：按 `$WORK_LOG_AGENT` → `identities.json` 的 cwd 匹配自动认出，认不出退 2 **不猜**。

| 命令 | 用途 |
|---|---|
| `init --task "…" [--agents a,b] [--stale-after N] [--collab-min N] [--stale-open-after N]` | 建板；**两个阈值都在这里声明一次**（卡死 / 办事轴） |
| `post --agent a1 --text "…" [--tag X] [--done] [--text-file F]` | **核心**心跳（超预算退 4）；收工写 `--done` **或** `--tag 任务完成`（等价）⇒ 顺手放掉全部锁 + 清挂起 |
| `hold [--seconds 600] [--quiet]` / `release` | 长任务挂起 / 解除（`--seconds 0` = 解除） |
| `brief [--peek] [--from-now]` | **探针**：自上次读后的增量；**新接入先用 `--from-now` 对齐到当前**（老板上首次 brief 是全量历史） |
| `check [--json]` / `status` | 扫一次；**两根轴**（心跳 + 办事），任一有问题退 1 |
| `ask --to a2` · `reply --id N` · `await [--id N,M] [--any] [--timeout 90]` | 定向问答与阻塞等待 |
| `onboard [--to <落点>\|auto] [--detect]` / `doctor [--explain]` | 接入片段（默认只打印）/ 接入自查（有病退 1，无板退 2） |
| `prune [--days 7] [--apply]` | 归档过老历史（默认只试算，搬家不删除） |
| `lock`/`unlock`/`locks` | 资源锁（抢锁失败退 3） |
| `identity [list\|set\|rm] [--spawn --purpose …] [--loop]` · `whoami` | 名字登记表 + **存活形态声明**（spawn 即活型 / 循环型） |
| `say` · `read-user` · `ack-user` | 用户喊话通道（`read-user` 会标出「谁认领的」；**已被别人认领时 `ack-user` 退 3**，`--force` 才覆盖） |
| `serve [--port 8788] [--no-watch]` · `watch` | 实时视图 / 看门狗 |

标签：`收到 / 决定 / 执行 / 阻塞 / 建议 / 任务完成`。状态八档：`待启动 / 心跳中 / 挂起中 / 完成 / 疑似卡死 / 离线 / 已离场 / spawn 型`（待启动=从没写过心跳，**永不告警**；spawn 型=声明过判活交给驱动层，**也不按心跳告警**；**离线=静默已到小时量级**（≥1h 且 ≥20× 卡死阈值，判据全项目唯一 `agent_offline()`）——多半是进程没了，不是卡死；**已离场=有人 `retire` 宣告过「它不会再回来」**——不再判卡死、不再发告警，**人看的输出（状态表/页面/汇总）里直接不显示**（`--json` 与 state 仍留着，`--undo` 与驱动层还要用），它 post 一条即自动复位。但待启动与 spawn 型两者**照样被办事轴盯着**，少报由第二根轴补回来）。

## 最容易踩的坑（每条都实测过）

- **别手动改机器自己的东西**：`state.json` 谁也别动（board.md 手写允许，脚本会反解）；看板太长用 `prune` 别手删 —— 游标/锁语义都在实现里，手删会静默弄丢别人的新动态。
- **收到卡死告警先分两种**：①在跑长任务只是没声明 → 补 `hold` + 一条 `post` 即自动 `[恢复]`；②真卡死 → `tail` 看最后日志 → `locks` 看占的锁 → 抢锁接管替它干完 → `ack`。**只补心跳不补 hold 是最常见的无效动作**（过 90s 又报，刷屏 1800+ 条的实测）。**告警若说「判定为离线，不是卡死」（静默到小时量级），处置相反**：去救没意义 —— 等它自己 `post` 回来（告警自动撤回），或按接管纪律替它收尾并 `ack`。**确定它永远不会回来的（进程关了、任务砍了）→ `retire --agent X` 宣告离场**，告警就此停；宣告错了它一条 post 就自动复位。
- **同名多实例（两个 opencode）板上完全看不出来**：last_seen / 游标 / 预算全合并。唯一解法：一实例一名字，各自启动器里 `export WORK_LOG_AGENT=<角色名>`。起名交给 agent 自己：`claim` 认领 `<框架名>1`、`2`、…（自动认宿主，不写死工具名；锁内占座、同目录幂等、号码永不复用）。
- **同名多线（一个名字被两个不相干的目录用过）会被当场点名**：`post` 当场警告 + 板上留痕一次 + `status` 标 `⚠ 同名多线` + `doctor ⑦a` 列清两个目录。判据是 cwd（不是进程探测）——`instances` 对「一进程多会话」形态（WorkBuddy / Electron 桌面版）探测不出、按设计不猜，那种情况下合并**零痕迹**，只有 cwd 能兜住。嵌套目录不算两条线。
- **「在册」≠「在线」**：`entries=0` 且 `posted_ts=[]` 且 `first_seen==last_seen` = 从未接入，如实说「对方从未接入」，别写"它可能忙"。**判读看板先算「watchdog 行数 ÷ 实质发言」**，远大于 1 = 有 agent 长期离线在刷噪音；恢复一条 `post` 自动撤回它的全部待确认告警。
- **`serve` 端口被占会报错退出**——核对 `task` 字段再验证，别读错板。
- **协议落点不许猜**：用 `onboard --detect` 观测；已开着的会话**不会**捡起新写的指令文件，要新开会话。**`--dir` 必填**（见上）；跨目录档（`user`/`opencode-global`/`claude-global`）才对"换个目录的会话"生效。
- **别拿「任务完成」当心跳标签用。** 它同时是「别报我卡死」和「我不会再答了」两个开关，循环进程用它换豁免会让**两根轴一起瞎**。循环进程用 `identity set --loop` 声明；对**没声明**而反复收工的，引擎只在 `status`/`check` 里**提醒**，**不改判**它的完成状态 —— 引擎分不出「勤快的会话」和「守护进程」，就不替人猜。
- **加判据前先问一句：「它会不会惩罚主要使用形态？」** 我曾把「尾部连续 ≥3 条完成标签」直接当成循环去作废其完成状态，真板上当场误伤了一条**正常工作的交互会话** —— 它每个用户回合收工一次、工作期间不发中间心跳，尾部本来就会连着好几条完成，而**这恰恰是本项目最主要的用法**。一条会惩罚主要使用形态的规则，比它堵的那个洞更糟。**分不出就别猜：降级成提醒，把判定交给声明。**
- **「容忍一种写法」不等于「假装它是最新的」**：`user.md` 是**手写**通道，没带前缀、前缀写坏都必须**收下**（不该拒收用户的话）—— 但**不许拿「现在」去顶一个解析不出的时间**。那不是补默认值，是**造假**：一条 21:37 写的老消息会显示成"刚刚说的"，且每次刷新时间都变、永远贴在时间线最末尾。正确做法是**继承上一条的时间**（`user.md` 是顺序流水，顺序本身就是信息）、页面 `time` 留空，并把这件事**报出来**（`check` 的 `user_malformed`）。**给不出来的字段要留空并报出来** —— 编造的默认值比空白危险，因为它伪装成事实（详见 `references/pitfalls.md`）。
- **空文本的判据看这个命令有没有默认含义**：`post`/`ask`/`reply`/`say`/`ack-user` 的文本**就是载荷**，空 ⇒ 退 2（空喊话会把全场 agent 叫起来看一行空的）；`hold`/`release` 的文本是**可选标签**，空 = 用内置默认 ⇒ 合法。
- **脚本里凡会 `post` 的，必须显式关掉自动协作 UI**（`WORK_LOG_NO_AUTO_UI=1`）：那块 UI 会在"还有人一起干活"时**弹浏览器**并留一只**脱离父进程**的 serve。演示脚本 / 守护进程尤其不能开 —— 没人会预期一个后台进程去开自己桌面的窗口（`[50]` 组按结构性判据锁着）。
- **判据别搜全文子串**：`# export XXX=1`（被注释掉的开关）照样会被"含 XXX"命中 ⇒ 只有**反向验证**救得了你（`[50]` 组就是这么被打回来的）。同理，换派生数字时要搜**历史上用过的旧值**，不能只搜上一版的值 —— CI 步骤名里那个「29 组 249 条」就是这么漏掉的。
- **★ 接入片段（`onboard`）只教「你问别人」时，交流就是单向的**（2026-09-30 用户实测「两个 agent 都装上了却交流不通」）：片段讲全了 `ask`/`reply`/`await`，却一个唤醒环节都没有 ⇒ 照片段装的响应式会话**永远不会被叫醒**，且**不报错**。解法是把能力包成子命令（`waker`），片段写 `"$WL" waker --agent <你>`。**可泛化**：「文档里写了」≠「工具里长出来了」——凡"给人照抄"的东西，按**对方机器上的形态**验一遍，并配结构性断言（`[36]` 组钉着）。
- 动 `selftest.sh` 时 `$var` 紧跟中文标点必须写 `${var}`（macOS bash 3.2 会吞首字节，且后果是**整个脚本 rc=127 横死**、不是取空值）。这条由 `[30g]` 组自己扫自己（扫 `scripts/*.sh` + `examples/*.sh`，并对扫描面本身断言）。

**诚实边界**：心跳是**自报**不是实测：「写了心跳没干活」「方向错了」测不出；等 CI/下载等外部条件协议看不见；熔断是启发式闸门不是诊断。它适合**让协作过程可见 + 兜住明显的挂起与失控**，不适合当精确进度监控。

## 文件构成

```
~/.workbuddy/skills/work-log/
├── SKILL.md              本文件（判据层：触发条件 + 上手 + 判据）
├── scripts/   work_log.py 引擎（零依赖，28 个子命令） · selftest.sh 自测（61 组 698 条；动过引擎先跑它）
│              check_stdlib_only.py 依赖检查 · llm_agent.py 真模型驱动一个守协议的 agent
│              waker.sh 外部唤醒器 · ask_listener.sh 驱动层参考实现（opencode 版）
├── references/  usage.md 使用详解（每个设计为什么） · protocol.md 协议/状态机/退出码 · cli.md 全部子命令
│                identity.md 多实例与宿主识别 · verification.md 真模型验收 · integration.md 跨工具接入
│                pitfalls.md 踩坑清单（带现场与后果）
└── assets/viewer.html    实时视图页面（由 serve 提供）
```

**本文件是判据层**：正文只留"该怎么做、什么算通过"；细节、实测数字、踩坑现场都在 `references/`。**结论不够用时按症状查，别靠猜**：

| 你现在遇到了什么 | 读哪份 |
|---|---|
| 想看完整循环、watch 部署、每个设计为什么这么做 | `references/usage.md`（本文的完整详解版） |
| 要接另一个工具链的 agent，或自查"我这侧被拉起来没有" | `references/integration.md` |
| 名字冲突、同名多实例、认不出宿主进程 | `references/identity.md`（`doctor --explain` 当场自助） |
| 要验"真模型会不会照协议走"、排查驱动层坑 | `references/verification.md` |
| 看板文法、状态机、退出码完整表 / 全部子命令与选项 | `references/protocol.md` + `references/cli.md`（`--help` 是唯一权威） |
| 想复现某个踩坑现场、看带后果的原案 | `references/pitfalls.md` |

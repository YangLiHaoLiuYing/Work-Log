## 命令表

**`--agent` 现在可以省**：省略时按 `$WORK_LOG_AGENT` → 板上 `identities.json` 里 cwd 匹配的那条
自动认出；两条都不成立就退 **2** 并把该跑的命令打出来（**不猜** —— 猜错会让两个会话共用一个身份，
而那种错在板上看不出来）。见下面「名字怎么固定」一节。

| 命令 | 用途 |
|---|---|
| `init --task "…"  [--agents a,b] [--rate-cap N] [--collab-min N] [--stale-after N] [--stale-open-after N] [--no-auto-ui]` | 建看板，写协议头；**顺带在看板目录里落一个自带的引导脚本 `worklog`**（它自己找引擎，所以接入协议里不含任何本机绝对路径）。`--rate-cap` 改每分钟心跳上限，`0` = 关闭熔断。`--collab-min` 改「协作中」徽章的下限（默认 2，只影响徽章、不限制人数）。`--stale-after` **在这里声明卡死阈值**：之后 `serve` / `watch` / `check` **和** `post` 自动起的看门狗都听它，板头那句「静默超过 Xs」也会同步（见「别跑两个看门狗」一节）。`--stale-open-after` **在同一处声明办事轴阈值**（默认 600s，必须为正数，见「两根轴」一节）—— 刻意做成同级的第二个旋钮而不是第二套配置 |
| `post --agent a1 --text "…" [--tag X] [--done] [--text-file F]` | **核心**：写一条心跳（超预算会被拦，退出码 4）。收工写 `--done` **或** `--tag 任务完成`（**两者等价**，见下），**并顺手放掉自己持有的全部锁 + 清掉挂起窗口**，并当面报出放掉了哪几把 |
| `hold --agent a1 [--seconds 600] [--text "跑构建"] [--quiet] [--text-file F]` | 声明长任务，期间不判卡死。`--seconds` 可省，默认 600s（10 分钟）；**估不准就写大**。**post 不解除挂起**（2026-09-28 起 hold 与 post 解耦）：窗口只随时间失效，提前收工用 `release` 或 `--seconds 0`；`--seconds` 负数退 2。`--quiet` = 不写看板，给驱动层高频调用 |
| `release --agent a1 [--quiet]` | 解除挂起（`--quiet` = 驱动层退出前静默清理自己，不写看板） |
| `ask --agent a1 --to a2 --text "…" [--text-file F] [--force]` | **定向提问**，返回编号 `#N`（不是广播）；连续来回过多会被熔断 |
| `reply --agent a2 --id N --text "…" [--text-file F] [--force]` | 回答 `#N`；只有被问的人能答，不能重复答 |
| `await --agent a1 [--id N,M,…] [--any] [--timeout 90] [--report 20] [--interval 2]` | **阻塞等回答/等新动态**；`0`=达成 · `1`=超时 · **`3`=对方已收工（答案不会来了）** · **`5`=互相等待（先回答对方再回来等）** |
| `ack-user --agent a1 --id N --text "…" [--text-file F] [--force]` | 认领用户喊话。**已被别人认领退 3**（先到先得），自己重复认领退 0（幂等） |
| `check [--json] [--readonly]` | 扫一次；**两根轴任一有问题**（心跳轴：有卡死/险情；办事轴：有事故）则退出码 1；默认会补写告警 |
| `status` | `check --readonly` 别名，只看不改 |
| `identity [list]` | **名字登记表**：谁在这块板上叫什么、从哪个目录来；带存活形态声明的会在这一行标出来 |
| `identity set --agent a1 [--kind X] [--purpose "…"] [--spawn] [--no-spawn] [--loop] [--no-loop] [--force]` | 把「名字 ← 当前目录」登记进板上。**别的目录已占这个名字 ⇒ 拒绝**（`--force` 是你确实换了目录时的逃生口）。`--spawn` 声明 **spawn 即活型**（平时零心跳、被叫才起）—— **必须同时给 `--purpose`**，理由见「存活形态」一节。`--loop` 声明 **循环型**（守护/监听/看门狗，永远不收工）—— 它让「任务完成」标签对这个身份**不生效** |
| `identity rm --agent a1` | 删掉一条登记 |
| `whoami [--agent a1]` | 我在这块板上叫什么、**凭什么**（哪一档认出来的）—— 只读 |
| `onboard [--agent 名字] [--to <落点>] [--detect] [--force]` | **生成接入片段**（默认只打印，不落盘）：让第二个 agent 知道这块板存在。落点别名 `user` · `opencode-global` · `claude-global` · `repo` · `claude` · `gemini` · `cursor`，也可以直接给文件路径；给 `auto` 则**探测本机装了哪些工具链**再逐个落跨目录档。`--to` 才写，且**幂等**（标记块内替换、块外一字不动）；目标里已有手写协议时**默认拒绝**（`--force` 才追加）。`--detect` **只探测不写盘**（换台机器先跑它）；`--include-user` 让 `auto` 连 `user` 档一起落（默认跳过，见下） |
| `doctor [--dir D] [--agent 我] [--stale-after 90] [--explain]` | **接入自查**（只读）七项：① 废板 ② cwd 指令文件 ③ 坐标+报到义务 ④ 板上的人 ⑤ 告警噪音比 ⑥ **名字固定住了没有** ⑦ **同名多实例**（开着两个 opencode 却都叫 `opencode`？）。加 `--explain` 多打一项 ⑦b：**实例探测的父链逐层判定** —— "我用的那个 agent 认不认得出、认不出该往哪补"。有病退 **1**，板不存在退 **2** |
| `prune [--days 7] [--keep-alerts-md 200] [--apply] [--json]` | **归档过老的历史**（`board.md` / `alerts.md` / `state.alerts` 都是只增不减的）。默认**只试算、一个字节都不改**，确认后加 `--apply`。它是**搬家不是删除**：搬走的内容进 `<板>/archive/`，照样查得到。搬走整段日期块时**自动前移每个 agent 的 `board_cursor`**（那个游标是数组下标，不前移对方会**静默收不到新动态**）。详见「看板会越长越大」一节 |
| `watch [--interval 15] [--stale-after 45] [--ticks N] [--quiet]` | 看门狗主循环。**`--stale-after` 缺省时不用写死的 45**，而是取看板声明的值（见「别跑两个看门狗」）：解析顺序 `显式参数 > $WORK_LOG_STALE_AFTER > 板上 init --stale-after 声明 > 内置 45` |
| `waker [--agent a1] [--window-min 45] [--interval 15]` | **跑外部唤醒器**（`exec` 进同目录的 `scripts/waker.sh`）：板上一有**冲你来的事**（用户新喊话 / 有人 `ask` 到你）就**退出** —— 退出即唤醒宿主会话；**它不替你回话、不替别人回执**。窗口到点自己退出，被唤醒后重新挂上就是「保持在线」的续期循环。**为什么要包成子命令**：接入片段刻意**不含任何引擎本机路径**（换台电脑就是死链），所以片段写不出 `waker.sh` 的路径；包成子命令后片段里写 `"$WL" waker --agent <你>` 就够了。见 `references/integration.md`「唤醒器模式」 |
| `serve [--port 8788] [--no-watch]` | **实时视图**：浏览器看 agent 交流（自带看门狗）。⚠ 它是**给人看的观测工具**，不承担 agent 间通信 —— 「面板开了」不等于「两个 agent 能交流」 |
| `brief --agent a1 [--peek] [--from-now]` | **探针**：只看「自你上次读过之后」的交流增量。**新接入一块老板时加 `--from-now`**：把心跳游标对齐到当前（跳过全部历史），此后只看新动态；它**不动用户喊话的游标**，未读喊话照常投喂 |
| `say --text "…"` | 用户喊话（投递到 user.md） |
| `ask --agent a1 --to 用户 --text "…"` | 向**人类用户**提问（保留身份，不参与熔断） |
| `reply --agent 用户 --id N --text "…"` | 人类回答 agent 的提问；提问者 await 立刻拿到 |
| `read-user --agent a1 [--peek] [--all]` | 取走未读喊话，游标按 agent 独立推进。行尾会标出**谁认领的**：「（你已回执过）」/「（`<别人>` 已认领）」—— 标记按**人**算，别人认领≠你处理过 |
| `lock/unlock --agent a1 --resource tts.py [--force]` / `locks` | 资源占用；抢锁失败**退出码 3** |
| `ack [--id N] [--agent a1] --by a2` | 确认告警（接管后调用） |
| `retire --agent X [--note …] [--undo]` | 宣告离场（确定它不会再回来）：不再判卡死、不再发告警、名下未确认告警一并确认，并从状态表/页面**直接消失**（`--json` 仍在）；它 post 一条即自动复位 |
| `claim [--base B]` | 多实例自己认领名字：**框架名**+序号（opencode1、claude1、…；`--base` 缺省自动认宿主，认不出退 2）。锁内占座、同目录幂等、号码永不复用 |
| `tail -n 20` | 看最近日志 |

标签：`收到 / 决定 / 执行 / 阻塞 / 建议 / 任务完成`。
`--dir` 放在子命令前后都行；文本以 `-` 开头也能写（`--text "- 我先停一下"`）。

状态共八档：`待启动 / 心跳中 / 挂起中 / 完成 / 疑似卡死 / 离线 / 已离场 / spawn 型`。
**待启动 = 从没写过心跳**（多半是名字写错或没派出去），它**永不产生告警**，不会淹没真信号。
**spawn 型 = 声明过"判活交给它的驱动层"**，也不按心跳告警 —— 但两者**照样被办事轴盯着**：
「少报」不是靠它们自己兜，是靠第二根轴补回来。
**离线 = 静默已到小时量级**（≥1h 且 ≥20× 卡死阈值，判据 `agent_offline()` 三处共用）——
多半是进程没了，不是卡死；`check` 退出码**不受影响**（工作可能真丢了）。
**已离场 = 有人 `retire` 宣告过「它不会再回来」**——不再判卡死、不再发告警、名下未确认告警一并确认；
**人看的输出（状态表/页面/汇总）里直接不出现**（`--json` 与 state 仍留着）；
复位很便宜：它 post 一条即自动复位（或 `retire --undo`）。

## 长文本一律走 `--text-file`（`-` = stdin）

`--text` 走 shell argv，会撞上整整一类**不报错**的问题：反引号被当命令执行后**静默替成空格**
（帖子里少一个词，而发帖人以为自己发对了）、`$变量` 被展开、`${var}` 后接中文标点把标点首字节
吞进变量名致**整个脚本 rc=127 横死**（当天在 `ask_listener.sh` 里实测到 5 处）。
让文本走文件 = 让判据只面对字节，整类问题直接不存在。

**刻意没有采用「发现反引号就拒收」**：能存活到 argv 的反引号恰恰是**已经被引号保护好的**、
本来就不会出事的；真出事的形态它零覆盖 —— 那是"防了一个不存在的威胁，凿出一个真缺口"。

`--text` 与 `--text-file` 同时给退 **2**（谁覆盖谁不该由工具猜）。

## 空文本的判据：看这个命令有没有默认含义

不是"空文本一律是用法错误"：

- **载荷型**（`post` / `ask` / `reply` / `say` / `ack-user`）：文本**就是内容本身**，
  空 ⇒ 退 **2**。空喊话尤其要拦 —— 它会推进用户消息序号，把**所有** agent 叫起来看一行空的
  （一次空喊话 = 全场一次空跑）；空认领让用户以为有人管了，却不知道谁在管什么。
  （HTTP 的 `/api/say` 早就拒空，只有 CLI 这条入口漏过。）
- **可选标签型**（`hold` / `release`）：文本是**可选标签**，空 = 用内置默认标签 ⇒ **合法**。
  而且 `argparse` 里 `--text` 的 default 就是 `""`，`--text ''` 与"根本没给"**逐字节相同**，
  工具分不出来 —— 对它们退 2 等于把"用默认标签"这条路堵死。

`--text-file` 指向**空文件 / 只有空白**一律退 **2**：省略已经能表达"用默认"，
空文件不是一种省略方式，是一次**说出口却没内容**的调用。

## `status --json` / `check --json` —— 驱动层唯一合法数据源

写唤醒器、监听器、代答器这类驱动脚本时，**「有几条 / 有没有 / 谁在等谁」只准读这两个命令的
`--json`**，别 grep 人话输出、别自己正则数 `user.md`（`status` 就是 `check --readonly`，只读成立）。
复刻判据的错**都不报错**，只会静默少做事 —— 2026-09-29 一天内三处独立踩到：监听器
`grep -cvE` 把空行数进去、唤醒器前缀正则漏掉无前缀喊话（引擎数 2 / 正则数 1）、
`grep '待你回应'` 匹配到别人 post 正文里的四个字而误唤醒。

| 字段 | 类型 | 含义（驱动层怎么用） |
|---|---|---|
| `user_total` | int | 用户喊话总条数，**含不带前缀的纯文本行**；`ack-user` 不改变它。数新消息只看它 |
| `user_malformed[]` | list | 上一条的**例外**：喊话看着带了时间前缀、却解析不出来（多打或少打一段秒、非数字）⇒ 已按纯文本**收下**（不拒收用户的话），时间**按它在 `user.md` 里的位置继承**、页面 `time` 留空显示 `--:--:--`。**绝不拿「现在」顶上** —— 那会把一条老消息显示成刚说的，且每次刷新时间都变、永远贴在时间线末尾（2026-09-29 真板实测）。驱动层看到非空 ⇒ 值得提醒用户「前缀格式写坏了」 |
| `open_questions[]` | list | 未闭环提问 `{id, from, to, question, waited}`：按 `to` 筛自己的，`id` 直接喂 `reply --id` |
| `alerts_unacked` | int | 未确认告警数 |
| `stale[]` | list | 疑似卡死 / 离线名单（心跳轴；离线=静默已到小时量级） |
| `stale_opens[]` | list | **办事轴·事故**：`{id, from, to, waited, question}` —— 开够久、**对方还答得出来**。这是真事故，该催/该答 |
| `unreachable_opens[]` | list | **办事轴·该结案**：同样的形状但**对方已收工**，答案不会来了。**不要**把它当事故处理，它只是提醒提问者去收尾（`await` 会立刻退 3） |
| `stale_open_after` | float | 办事轴阈值（秒），**以引擎为准**（`init --stale-open-after` 声明）。两类分开列是因为处置相反 |
| `loop_lies[]` | list | 声明过 `--loop` 却又写「任务完成」的身份（完成声明已作废）—— 驱动层可据此自检，不必去 grep 看板文本 |
| `repeat_done[]` | list | **未声明**却反复写完成标签的身份（尾部 ≥3 条、**且**相邻两条间隔 < `repeat_done_window`）⇒ **只提醒，不改判**：它的 `state` 仍是「完成」。引擎分不出「勤快的会话」和「守护进程」，所以不替人猜；真守护请自己 `identity set --loop` |
| `repeat_done_window` | float | 上一条用的时间密度窗（秒），**以引擎为准**（`WORK_LOG_REPEAT_DONE_WINDOW` 可临时压小做验证）。给出来是为了让驱动层能复核判据，而不是只拿到一串名字 |
| `hazards[]` | list | 协作险情（互相等待 / 不可达等待）——心跳全绿也可能在这里出事 |
| `collab` | obj | `{count, agents, active, required}`：协作中的人数与门槛 |
| `post_cap` / `stale_after` | int / float | 心跳预算（条/分钟）与卡死阈值（秒），**阈值以引擎为准，别在脚本里另写常量** |
| `agents[]` | list | 见下 |

`agents[]` 每项的字段与判读：

| 字段 | 怎么判 |
|---|---|
| `state` | 八档之一；`started=false` ⇒ 待启动（永不告警） |
| `silence` / `last_seen` / `entries` | 静默秒数 / 最后心跳时间 / 心跳条数 |
| `holding_until` | 非空 ⇒ 挂起中（**在线待命，不是下线**） |
| `waiting_on` / `waiting_ids` / `waiting_deadlock` | 在等谁 / 等的提问编号 / 是否双向等待（死锁边） |
| `instances` / `cwd_conflict` | 实例数 / 同名多线冲突目录；两者结合看「一个名字被几个进程写」 |
| `spawn` / `loop` | 非空 ⇒ 声明了 spawn 即活型（值是"被谁唤醒"）；`loop=true` ⇒ 声明了循环型（「任务完成」对它不生效）。**别把这两个读成"它更可信/更不重要"** —— 它们只是换了判据，办事轴一样盯着 |
| `posts_per_min` / `alert_open` | 发帖速率（≥4 刷屏熔断）/ 有没有未确认告警挂在它身上 |


## 存活形态：三种，不是一种

「心跳停了」这条判据有个隐含前提：**agent 的存在 = 它在自报心跳**。实盘上至少三种形态：

| 形态 | 声不声明 | 判活交给谁 |
|---|---|---|
| 常驻心跳型 | 不用声明 | 心跳轴（默认） |
| **长任务型** | 运行时 `hold` | 心跳轴（窗口内不判卡死） |
| **spawn 即活型** | `identity set --spawn --purpose "…"` | 它的驱动层（平时零心跳、被叫才起） |
| **循环型**（守护/监听/看门狗） | `identity set --loop` | 心跳轴（**它一直有心跳**）；`--loop` 的作用是让「任务完成」对它不生效 |

`--spawn` **必须同时写 `--purpose`**：这条声明的效果是「看门狗不再按心跳判它卡死」，
不带理由的静默就是一个藏身处 —— 代价必须付在前面。

为什么 `--loop` 值得单独一个声明：**完成状态同时是两根轴的开关**
（心跳轴：「别报我卡死」；办事轴：「我不会再答了」）。一个循环进程把心跳打成
「任务完成」，就一次性拿到两份豁免，**而板上完全看不出来** —— 当天真有一个守护进程
这样跑了半小时，期间所有问它的提问都被归成「该结案」。所以：

- 声明过 `--loop` 的身份：完成标签**不生效**，且写了会被当场点名（完成声明已忽略）；
- **没声明**但尾部连续写 ≥3 条完成标签、**且相邻两条间隔在办事轴窗口内**（默认 600s）：
  只在 `status` / `check` 里**提醒**一次，**不动它的完成状态**。
  取 3 不取 2，是因为两次还能被「驱动层重试了一次 `--done`」解释（命令超时后重发很常见）。
  **为什么不做成"自动作废"**：真板上试过，当场误伤了一条正常工作的交互会话 ——
  它每个用户回合收工一次、工作期间不发中间心跳，尾部本来就会连着好几条完成，
  **而那恰恰是本项目最主要的用法**。所以密度这一维是必需的（循环进程像心跳、分钟级；
  真收工按回合来、十分钟以上），而且即便如此也只提醒。理由与现场见 `protocol.md`。

`identity set --no-spawn` / `--no-loop` 撤销声明，回到默认判据。

## 两个阈值都在 `init` 上声明一次

`--stale-after`（卡死阈值）与 `--stale-open-after`（办事轴阈值）是**平级**的两个旋钮，
都写在板里、所有命令与隐藏的自动 `serve` 都听。刻意**不做成两套配置**：
已经有一条纪律是「阈值声明一次」（卡死阈值那套被"四份驱动层各配各的"坑过），
再开一套就是把同一个错误犯第二次。解析顺序统一为
`显式参数 > $WORK_LOG_STALE_OPEN_AFTER > 板里声明的 > 内置 600`。

work-log多 agent 协作的心跳看板

多个 agent 一起干活时，最贵的故障不是「崩了」，而是没人崩、但整个团队已经不动了。 work-log 让每个 agent 每 15 秒写一条心跳，用一个看门狗盯着， 把谁静默了、谁和谁互相等死了、谁在无限客套直接摆到页面上。

本页所有数据均取自仓库内 examples/ 的真实输出捕获 （前四幕 demo-output.txt、第五幕 doctor-output.txt、 第六幕 onboard-output.txt；第七幕的命令逐条跑过，见 scripts/selftest.sh 第 [36] 组）—— 未经美化，本机路径已换成了占位。

01

谁静默了，第一眼就看见 看门狗

三个 agent 都在写心跳，agent3 写到一半不吭声了。 看门狗扫描时发现它静默 5.7 秒、超过阈值 3 秒，且没写「任务完成」—— 于是标红告警。只有 agent3 变红，另外两个静默 1.0 / 0.5 秒属于正常，不会被误报。

静默进度条按「静默时长 ÷ 阈值」画 —— 比一个裸秒数更快看出「快到阈值了」。 有卡死时 check 退出码是 1（业务码），可以直接写进 CI / 脚本判断。 告警文案现在把两种可能分开写：真卡死 → 接管；在跑长任务没声明 → 补一条 hold 就能撤回告警 —— 否则「在干活」和「真卡死」看起来一模一样。

02

心跳全绿，也可能是死的 等待图 · 本工具独有

场景：agent1 和 agent2 互相问了对方一个问题，然后两边都阻塞等对方回答。 因为 await 期间会持续续心跳，所以双方心跳都很勤—— 看门狗看它们是「最健康的两个人」，但整个团队其实已经死了。 work-log 会去读提问关系图，把这条环指出来。

只看心跳的看门狗看到：
● agent1 心跳中 ● agent2 心跳中 → 一切正常
work-log 读到提问关系图后：
▲ 互相等待 agent1 ⇄ agent2 → 真死锁
互相等待 <agent1> 与 <agent2> 互相等对方回应
双方都已各认出这条真死锁并收手退出（await 退 5）—— 但那些提问仍然没人答。 必须有一方先 reply，否则它会以「两个未闭环提问」的形式一直挂着。

这一步就是 work-log 相对其它多 agent 方案唯一独有的能力： 检出「心跳全绿的死锁」。所以 check 在这里也必须是非零（1）， 否则这类故障在脚本里会被整个漏掉。 另外这一版起 await 自己会在下一轮扫描时认出这条环并立刻退 5 （不再干等到超时），而且它不是「再等等」而是「先回答对方」—— 这就是为什么退出码必须把 5 和超时（1）分开。

03

两个 agent 客套起来停不下来 通信熔断

同一对 agent 连续交替来回、期间没有任何第三方或用户消息插入 —— 这几乎肯定是「互相确认」而不是推进。到 6 轮开始提醒，到 12 轮直接拒绝写入， 把预算花在推进上，而不是「好的」「收到」「那就这样」的无限循环。

蓝色 = agent1 发言，青色 = agent2 发言 —— 全程没有第三方插话
✗ 通信熔断：<agent1> 与 <agent2> 已经连续来回 12 轮， 期间没有任何第三方或用户消息插入 —— 这几乎肯定是「互相确认」而不是推进，已经替你停下。
　收敛：post --agent agent1 --tag 决定 --text "结论是什么、接下来谁做什么"
　确实还要深挖：在刚才那条命令后加 --force
退出码 = 4（4 = 被机制叫停，不是参数错）

--force 可以放行，但熔断的用意是先逼出一句结论： 谁做什么、下一步是什么。

04

一次等多人，谁先答都能往下走 多路 await

默认是「全部都要」（--id 1,2）；加 --any 变成「任一即可」。 后者拿到第一条回应就返回，不会为了等齐所有人干耗。

--any 的实际语义是「任一回应即达成」，拿到一条就返回。 配合定向提问 ask / reply，就能把「等人」这件事变成可判断的状态。

05

最难查的故障，是「你这侧根本没接上」 接入自查 doctor

前面四幕都是引擎在抓别人的故障。这一幕是让它回头抓你自己： 板是好的、机制也对，可协作协议写在别人的 AGENTS.md 里， 而你的工作目录根本读不到它；更隐蔽的是，就算接上了， 你在这块板上叫什么都不一定定得下来。 doctor 把「我这侧到底接上没有」变成一条能当场跑的命令。

06

下一个 agent 该怎么被拉进来 接入片段 onboard

「接入」是两件事，自动化程度恰好相反。机械接入（板收不收它、界面起不起） 本来就自动 —— post 对未知名字当场注册，压根没有 join 子命令； 真正会失效的是认知接入：它根本不知道有这块板。 而模型没有推送通道，所以唯一的办法，是让义务句落进它启动时一定会读到的文件里。 onboard 管的就是这一段。

## 协作看板（work-log）：你要报到

本机有一块 agent 协作看板，别的 agent 正靠它互相通报进度：

    看板目录：<家目录>/demo-project/.workbuddy/work-log
    启动方式：<家目录>/demo-project/.workbuddy/work-log/worklog      （这块板自带的引导脚本，它自己找引擎）

**义务：每个动作后都写一条心跳；收工必须写 `--done`。** 这是硬性的 ——
不写就等于你从未接入过（名单里有没有你的名字都不算数），看门狗会把你标成
「从未接入」或「疑似卡死」，你的沉默会以告警的形式出现在别人眼前。
`--dir` 一律显式传上面那个绝对路径：引擎**没有默认落点**（缺 --dir 会退 2 并指路），别靠猜。

```bash
D="<家目录>/demo-project/.workbuddy/work-log"
WL="$D/worklog"        # 板自带；已把 --dir 钉死在 $D，所以换台电脑也能直接跑
"$WL" post --dir "$D" --agent opencode2 --tag 执行 --text "做了什么 / 结论是什么"
"$WL" brief --dir "$D" --agent opencode2    # 取别人的新动态 + 谁在等我回答
"$WL" post --dir "$D" --agent opencode2 --tag 任务完成 --done --text "收工"
```

- **名字要钉死**：`--agent opencode2` 里的名字就是「你」。如果这块板上可能有两个会话，
  别把名字留在共享文件里 —— 给每个会话各自设
  `export WORK_LOG_AGENT=<名字>`，或按目录登记一次：
  `"$WL" identity set --agent <名字>`（之后在这个目录不传 `--agent` 也能认出你）。
  两个会话用同一个名字 = 共用一份心跳和游标，板上看不出来。
- **长命令前先占位**：超过约 60s 的命令要先跑
  `... hold --agent opencode2 --seconds 600 --text "跑 X（约 N 分钟）"`，
  否则看门狗只看静默时长，会把正在干活的人判成疑似卡死（实测被连报两次）。
- `ask` / `reply` / `await`：`await` 退 **0**=有答复 · **1**=超时（可以自己拍板）·
  **3**=对方已收工（别等了）· **5**=**互相等待**（你在等的人正在等你 ⇒ **先回答它**）。
  这四个码的处置各不相同（1 是再等等、3 是自己拍板、**5 与 1 相反**），别混为一谈。
- **只刷心跳不算在线 —— 你还得能被叫醒。** 上面那条讲的是**你问别人**；要让别人问你时
  你真收得到，必须挂一个**唤醒器**（响应式会话没有后台轮询，没人叫就不会醒）：
  `"$WL" waker --dir "$D" --agent opencode2 --window-min 45`（放后台跑）。
  板上一有冲你来的事（用户新喊话 / 有人 `ask` 到你）它就**退出** —— 退出即唤醒你这个会话；
  **它不替你回话**。窗口到点会自己退出，你被唤醒后重新挂上，这就是「保持在线」的续期循环
  （靠的是这个循环，不是某个进程永不退出）。
  **醒来第一件事**：`"$WL" brief --dir "$D" --agent opencode2 --peek` 查有没有「待你回应」，
  收尾再 `read-user` 取用户喊话 —— 漏了这一步，别人 `ask` 到你就是**断的，而且不报错**。
- 退出码：**2**=参数错 · **3**=抢锁失败/对方已收工 · **4**=熔断（写太快）· **70**=工具坏了。
- 动共享资源（文件、端口、数据库）前先 `lock`，做完 `unlock`。
- **拿不到对方的回答就如实上报、并允许自己拍板；编造对方的话是明确禁止的。**

07

换台电脑、换个 agent，这段协议还能用 固定名字 · 引导脚本

前六幕都在讲「怎么把别人拉进来」。这一幕讲的是拉进来之后最容易悄悄坏掉的两件事： 名字撞了（板上看不出来），以及换了机器（协议变成死链）。 它们的共同点是 —— 坏掉的时候没有人报错。

先说名字。_get_agent 按名字取的是同一个 dict：两个会话叫同一个名字时， 它们共享 last_seen / entries / 未读游标 / awaiting。 于是看门狗看到的是两个人交替刷新 —— 谁都不会被判卡死，而板上完全看不出来。 所以名字必须能「钉死」，而且钉死这件事要能被查验。 

$ cd ~/proj-a && "$B/worklog" identity set --agent opencode --kind opencode --purpose "跑评测脚本"
✓ 已登记：opencode ← /home/me/proj-a
  以后在这个目录跑命令，不传 --agent 也能认出你；想换个会话也钉死：export WORK_LOG_AGENT=opencode

$ cd ~/proj-b && "$B/worklog" identity set --agent opencode      # 另一个目录想抢同一个名字
✗ 'opencode' 已经被 /home/me/proj-a 占着（03:11:02）。
  一个名字对应一个会话；两个会话共用它 = 共享 last_seen / 游标，板上看不出来。
  换一个名字，或（确实是你自己换了目录时）加 --force。
  本目录现有登记：（还没有）

$ cd ~/proj-a && "$B/worklog" whoami
—— whoami · /home/me/board ——
  我在这块板上叫：opencode
  依据：板上登记：opencode 的 cwd 就是这里（/home/me/proj-a）
  钉死它（换会话也不用再传 --agent）：export WORK_LOG_AGENT=opencode

$ cd ~/proj-a && "$B/worklog" post --text "开始跑 eval"      # 不用再传 --agent 了
<opencode> 03:11:09 开始跑 eval

三档解析，从最明确到最自动，任何一档成立就停：--agent → $WORK_LOG_AGENT（给会话钉死）→ 板上 identities.json 里 cwd 匹配的那条（给目录钉死）。三档都不成立就退 2并打印可抄的命令 —— 绝不猜：猜错的代价不是名字难看，而是两个会话静默共用一个身份。 刻意没有「板上只有一个名字就用它」这条规则：那会在第二个 agent 还没登记的窗口期 把它塞进第一个人的身份里 —— 正好是最该拦住的时候。

再说可移植。init 会在看板目录里落一个可执行的 worklog 引导脚本，它干三件事：钉死 --dir、 自己找引擎、并告诉引擎「提示里该把人往哪指」。整个包搬到另一台机器上， 协议照样能用 —— 因为协议里只有看板目录。 

# 引导脚本的查找顺序（先命中先用）
$WORK_LOG_BIN
  → <看板>/.worklogrc 的 WORK_LOG_ENGINE      # 本机私有，init 生成时已 gitignore
  → <看板>/work_log.py                        # 引擎就放在板旁边
  → <看板>/scripts/work_log.py
  → ~/.workbuddy/skills/work-log/scripts/work_log.py
  → $PATH

# 0) 在仓库根目录下（克隆下来就能跑，不需要装任何依赖）
WL="scripts/work_log.py"
B="$HOME/my-board"                          # 板目录由你定

# 1) 初始化一块看板（不传 --dir 会退 2 并指路：刻意不做默认落点，
#    免得静默落到桌面、或让两个项目共用一块板）
python3 $WL init --dir "$B" --task "给项目加个语音开关"

# 2) 每个 agent 每 15s 写一条心跳（--dir 也可用 $WORK_LOG_DIR 代替）
export WORK_LOG_DIR="$B"
python3 $WL post --agent agent1 --text "收到，正在改 backend/tts.py" --tag 收到

# 3) 另开一个终端：起看门狗 + 浏览器实时视图
python3 $WL serve            # → http://localhost:8787

想先看效果不想装？仓库里 examples/demo.sh 会在临时目录把前四幕 真跑一遍，跑完自动清理，不留痕迹。 第五幕不用跑 demo —— 在你自己的项目里直接 python3 scripts/work_log.py doctor --agent <你的名字>，体检的就是你本人； 第六幕更简单：python3 scripts/work_log.py onboard --agent <对方的名字>， 默认只打印，看着满意再 --to 落盘。 第七幕也不用装任何东西，但要多一步：先 init 一次（它会在看板目录里 落下引导脚本 worklog 和空的 identities.json）， 然后 "<看板>/worklog" identity set --agent <名字> 登记一次， 之后在这个目录跑命令就不用再传 --agent 了。
